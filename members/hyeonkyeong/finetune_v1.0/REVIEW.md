## 2. 무엇을 틀렸나 (ckpt-632)

정답 유형 → 모델이 고른 유형

| 정답 \ 모델 | 지표 JSON | 되묻기 | 거절 | JSON 깨짐 |
|---|---|---|---|---|
| 지표 JSON (67) | **0** | 33 | 32 | 2 |
| 되묻기 (30) | 0 | 26 | 4 | 0 |
| 거절 (14) | 0 | 3 | 11 | 0 |

**값이 들어 있는 원칙을 한 번도 지표 JSON으로 바꾸지 못했다.** 되묻기·거절은 어느 정도 배웠다.

예시
- "부채비율이 150퍼센트 미만이면 좋겠어" → 거절: "부채비율은 아직 쓰지 않는 지표예요" (부채비율은 1번 지표)
- "빚이 자기 돈의 두 배를 넘으면 안 돼요" → 값(200%)을 말했는데 되묻기: "어느 정도까지 괜찮을까요?"
- "현금 많이 쌓아둔 회사 찾아줘" (20개 밖 → 거절이 정답) → 없는 지표로 되묻기

## 3. 원인: 학습 데이터 비율

채점 오류는 아니다. 학습 데이터에서 첫 답의 유형을 세면 다음과 같다.

| 첫 답 유형 | 건수 |
|---|---|
| 되묻기 | 438 (S3 340 + SEED 98) |
| 거절 | 304 (그중 "아직 쓰지 않는 지표" 152) |
| **값을 바로 지표 JSON으로** | **84 (SEED뿐, 전체의 4%)** |
| 수정·용어 설명 (S4·S6·S7) | 1,264 |

- 말 → 지표 JSON 예시(S1·S2)가 없어서, 모델이 "원칙 문장 = 되묻거나 거절"로 배웠다.
- 데이터 속 "아직 쓰지 않는 지표" 거절은 ROE·배당성향·영업이익률처럼 실제로 20개 밖인 것만 들어 있다(데이터 오류 아님). 예시가 많아 모델이 실제 지표에도 거절을 일반화했다.
