# Qwen3-8B fixed-4 데이터 학습 결과 (hyeonkyeong, 2026-11-09)

yappang 통합 데이터 `q4b-final-data-fixed4-2026-11-09`(fixed-4, 8B·4B 공용)로 Qwen3-8B를 처음부터 학습했다.
같은 234문제로 지금 앱에 붙은 data_v6 3에폭(해찬 v5 재현, [결과 문서](8B_data_v6_재학습_결과.md))과 비교했다.

**결론: 추출 정확도에서 data_v6 3에폭이 앞선다 → 앱 모델은 data_v6 3에폭을 그대로 쓴다.**
단, 두 데이터는 정답 표기 기준(부등호 등)이 일부 달라서, 점수 차이의 일부는 "평가 정답 기준과의 차이"일 수 있다(4장, 아직 확인 전).

### 문제 세트별 추출 전체 일치 (맞은 수 / 추출 건수)

| 세트 | fx 2에폭 | fx 3에폭 | v6 3에폭 |
|---|---|---|---|
| 공식 111 (67건) | 61 | 60 | **65** |
| 해찬 58 (36건) | 32 | 28 | **34** |
| 해찬 34 (16건) | 12 | 12 | **13** |
| 해찬 31 (21건) | 16 | 15 | **19** |

- data_v6가 네 세트 모두에서 추출이 앞선다(3에폭끼리 140건 중 16문제 차이).
- fixed-4가 앞선 것은 2에폭 거절 정확도, 3에폭 사용자 지정 지표 정확도뿐이고 1~3문제 차이다.
- fixed-4는 3에폭이 2에폭보다 떨어졌다. val loss는 계속 내려갔는데(아래) 점수는 반대로 갔다.
- 참고: v6 3에폭의 공식 111 추출이 오전 평가 64/67(95.5)에서 이번 65/67(97.0)로 1문제 다르다. 평가 묶음(배치) 구성이 달라 생기는 흔들림 범위로 본다. 해찬 v5(97.0)와 같은 수준.

### val loss (fixed-4, 230스텝마다)

| 스텝 | 230 | 460 (≈1에폭) | 690 | 920 (≈2에폭) | 1150 | 1380 (≈3에폭) |
|---|---|---|---|---|---|---|
| val loss | 0.0303 | 0.0181 | 0.0092 | 0.0065 | 0.0065 | **0.00646** |

- val 데이터가 data_v6와 달라서 val loss로 두 모델을 비교하면 안 된다.

## 2. 두 학습 데이터의 차이

| | data_v6 | fixed-4 |
|---|---|---|
| train 대화 수 | 5,603 | 6,942 |
| val 대화 수 | 319 | 314 |
| 양쪽에 똑같이 있는 대화 | 5,122 | 5,122 |
| 한쪽에만 있는 대화 | 481 | 1,820 |
| system 프롬프트 | 2종 | 2종 (v6와 같음) |

- 바탕은 거의 같다. fixed-4는 v6에 없던 대화 1,820개가 더 있다(yappang 통합분으로 보임).
- v6에만 있는 481개에는 해찬 aug6 보강 247행(평가에서 틀린 유형 보강)이 들어 있을 가능성이 높다. **확인 전.**
- 평가 문장(test_set 234)이 학습 데이터에 그대로 들어간 경우: **두 데이터 모두 0건** → 외워서 오른 점수는 아니다.

### 같은 입력인데 정답이 다른 대화: 456개

| 바뀐 부분 | 개수 | 예 |
|---|---|---|
| 되묻기 후보 키 이름 `name` → `label` | 363 | `{"id": 8, "name": "매출액 증가율"}` → `{"id": 8, "label": ...}` |
| 지표 부등호 기준 | 71 | 영업이익 `> 0` → `>= 0` (31), `>= 5%` → `> 5%` (6), `<= 1배` → `< 1배` (4) 등 |
| 되묻기 안내 문구 | 24 | |
| 기타 (indicator_id, options) | 4 | |

- `name`/`label` 차이는 형식만 다르고 내용은 같다. hyeonkyeong 백엔드(`backend/llm/principle.py`)는 `label`·`name`·`area`를 모두 읽으므로 앱 동작에는 영향 없다.
- 부등호 기준 변경은 이상·이하 / 초과·미만 해석을 다시 정한 것으로 보인다.

## 3. 학습·평가 방법

### 학습
- 데이터: `data_fixed4/train_fixed4.jsonl`, `val_fixed4.jsonl` (`test_set.jsonl`은 평가용)
- 코드: `members/haechan/finetune/train_qlora.py` (data_v6 학습과 같은 코드·설정)
- `--epochs 3 --batch 2 --accum 8 --eval-steps 0`, lr 1e-4, LoRA r32/α64, seed 42
  - 에폭당 461스텝, 총 1,383스텝, 230스텝마다 평가·체크포인트
- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
- 서버 ws6 (RTX 4090 24GB), **2시간 28분**, VRAM 약 18GB
- 환경은 data_v6 학습과 같다(torch 2.11.0+cu128, transformers 4.57.6, peft 0.21.2, bitsandbytes 0.50.2).

### 평가
- `members/haechan/finetune/eval_model.py --data data_fixed4/test_set.jsonl`
- test_set 234문제 = 공식 111(`official111`) + 해찬 58 + 해찬 34 + 해찬 31 (`source` 필드)
- 비교 대상: fx 1·2·3에폭 = `checkpoint-460`·`920`·`1383`, v6 3에폭 = data_v6 `checkpoint-1131`
- 세트별 점수는 문제별 결과 jsonl을 `test_set.jsonl`의 `source`로 나눠 다시 셌다.

## 4. 아직 확인 못 한 것

1. **fixed-4가 틀린 문제가 진짜 오답인지, 정답 기준(부등호 등) 차이인지.** test_set 정답은 v6와 같은 기준일 가능성이 크다. 그렇다면 fixed-4는 기준을 바꾼 문제에서 채점상 틀린 것으로 나왔을 수 있다.
2. v6에만 있는 481개가 무엇인지(aug6 보강분인지).
3. 1번 결과에 따라 평가 정답 기준을 팀에서 하나로 정할 필요가 있다(이상/초과 해석).
