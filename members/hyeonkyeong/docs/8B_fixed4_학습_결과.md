# Qwen3-8B fixed-4 데이터 학습 결과 (hyeonkyeong, 2026-11-09)

yappang 통합 데이터 `q4b-final-data-fixed4-2026-11-09`(fixed-4, 8B·4B 공용)로 Qwen3-8B를 처음부터 학습했다.
같은 234문제로 지금 앱에 붙은 data_v6 3에폭(해찬 v5 재현, [결과 문서](8B_data_v6_재학습_결과.md))과 비교했다.

**결론: 두 모델은 비슷하고 강점이 다르다. 앱 모델은 data_v6 3에폭을 그대로 쓴다.**
- 채점표 그대로는 추출 전체 일치가 fx 3에폭 82.1 vs v6 93.6으로 크게 낮다. 하지만 원인은 대부분 **`anchors` 필드 누락**이다(2장). 지표 자체는 맞혔다.
- 앱 백엔드처럼 `anchors`를 채워서 다시 채점하면 추출은 fx 3에폭 **95.0** vs v6 **93.6**으로 fixed-4가 2문제 앞선다.
- 되묻기 사유 일치(75.0 vs 82.1)와 거절 정확도(78.9 vs 84.2)는 v6가 낫다.
- `anchors` 누락의 원인은 fixed-4 학습 데이터에 새로 들어온 **`indicators` 필드만 있는 정답 400개**다(3장).
- "v6는 평가 데이터가 학습에 섞였다"는 의견을 확인했다. v6에만 섞인 평가 문장은 없다(4장).

> 처음 올린 이 문서(c53003f)에는 "추출 정확도에서 data_v6가 앞선다"고 썼는데, 틀린 결론이었다. 오답을 하나씩 열어 보고 위와 같이 고쳤다.

## 2. fixed-4 점수가 낮게 나온 이유: `anchors` 누락

fx 3에폭은 틀리고 v6 3에폭은 맞힌 추출 문제 21개를 하나씩 열어 봤다(반대 경우는 5개).

| 원인 | 개수 | 예 |
|---|---|---|
| **지표는 다 맞혔는데 `anchors` 필드를 안 씀** | **17** | "차입금의존도 25% 이하만 볼래요", "영업이익 500억 넘는 회사 찾아줘" |
| 부등호가 다름 | 2 | "52주 최고가보다 30% 넘게 떨어진 주식은 빼줘": 정답 `>= -30`, 예측 `< -30` |
| 값을 다른 지표에 넣음 | 1 | "1년 최저가 대비 25% 이하로 오른 주식": 17번 대신 16번에 넣음 |
| 되묻기로 답함 | 1 | 오타 문장 "영업리익 흑자인 회사만" |

- `anchors` = 사용자가 직접 말한 지표 id 목록. `eval_model.py`는 지표가 다 맞아도 `anchors`가 정답과 다르면 전체 일치에서 틀린 것으로 친다.
- 모델 예측 중 지표를 뽑는 답에 `anchors`가 없는 비율: fx 3에폭 48/171, v6 3에폭 32/172.

## 3. 원인: fixed-4에 새로 들어온 `indicators`만 있는 정답 400개

학습 데이터에서 지표를 뽑는 답 중 `anchors`가 없는 답: v6 477개(19%), fixed-4 939개(31%).

| `anchors` 없는 답의 출처 (fixed-4 기준) | 개수 | 내용 |
|---|---|---|
| v6에도 있던 것 | 477 | 전부 **거절** 답(`indicators`·`message`·`refusal`). 예: "배당성향 높은 곳만 보여줘", "MACD 높은 회사만 보여줘". 사용자 지정 지표가 0개라 `anchors`가 필요 없다. |
| **fixed-4에 새로 들어온 것** | 462 | **400개는 `indicators` 필드 하나만 있는 일반 추출 정답**(사용자 지정 지표 1개 260, 2개 113, 3개 27). 나머지 62개는 거절. |

- 새로 들어온 400개의 예: "이자보상배율 6배 이상인 회사만 보여줘", "나는 차입금의존도 24% 이하이면 좋겠어", "자본잠식률 30% 이하인 종목 찾아줘"
- 이 400개에는 `anchors`뿐 아니라 이름(`name`)·설명(`explain_*`) 필드도 없다. 다른 데이터에서 형식을 줄여 가져온 것으로 보인다(출처는 yappang 확인 필요).
- 모델이 "단순한 지표 문장에는 `indicators`만 쓴다"를 배워서 평가에서 `anchors`를 빼먹었다.
- **다음 데이터 버전에서 이 400개에 `anchors`(사용자 지정 지표 id), `name`, `explain_*`를 채우면 채점 점수가 오를 것이다.**

## 4. "v6는 평가 데이터가 학습에 섞였다"는 의견 확인

| 확인한 것 | v6 train | fixed-4 train |
|---|---|---|
| 평가 문장(test_set 234)이 그대로 있음 | 0 | 0 |
| 거의 같은 문장 (띄어쓰기·문장부호·"요"를 빼고 유사도 0.85 이상), 공식 111 중 | 10 | 11 |
| 같은 기준, 해찬 34 중 | 0 | 1 |
| 유사도 0.75 이상 (공식 111 / 해찬 58 / 34 / 31) | 42 / 14 / 3 / 6 | 46 / 15 / 4 / 8 |

- 거의 같은 문장의 예: 평가 "PER 12배 이하인 주식" ↔ 학습 "PER 10배 이하인 주식", 평가 "ROA 높은 회사만 보여줘" ↔ 학습 "ROA가 높은 회사들만 보여줘". 숫자나 어미만 다른 템플릿형 문장이다.
- **v6에서 찾은 비슷한 문장 10개는 모두 fixed-4 train에도 똑같이 있다.** 비슷한 문장은 오히려 fixed-4가 조금 더 많다. 그래서 이 점으로 v6가 더 유리할 수는 없다.
- 간접 영향: 해찬 보강 스크립트(`data_aug/gen_aug_v6.py`)는 평가에서 틀린 유형을 보고 보강 데이터(aug6)를 만들었다. 평가 문장과 비슷한 것(유사도 0.75 이상)은 걸러냈다. 평가 결과를 보며 데이터를 다듬은 것은 맞다. 이 보강분 입력은 fixed-4 train에도 들어 있어 두 모델 조건이 같다.
- 정리: **평가 문제를 외워서 점수가 오른 것은 아니다.** 평가를 참고해 데이터를 다듬은 영향은 두 모델에 같이 있다.

## 5. 두 학습 데이터의 차이

| | data_v6 | fixed-4 |
|---|---|---|
| train 대화 수 | 5,603 | 6,942 |
| val 대화 수 | 319 | 314 |
| 양쪽에 똑같이 있는 대화 | 5,122 | 5,122 |
| 한쪽에만 있는 대화 | 481 | 1,820 |
| system 프롬프트 | 2종 | 2종 (v6와 같음) |

- v6에만 있는 481개는 대부분 **입력은 fixed-4에도 있고 정답 표기만 다른** 대화다(아래 456개).

### 같은 입력인데 정답이 다른 대화: 456개

| 바뀐 부분 | 개수 | 예 |
|---|---|---|
| 되묻기 후보 키 이름 `name` → `label` | 363 | `{"id": 8, "name": "매출액 증가율"}` → `{"id": 8, "label": ...}` |
| 지표 부등호 기준 | 71 | 영업이익 `> 0` → `>= 0` (31), `>= 5%` → `> 5%` (6), `<= 1배` → `< 1배` (4) 등 |
| 되묻기 안내 문구 | 24 | |
| 기타 (indicator_id, options) | 4 | |

- `name`/`label` 차이는 형식만 다르고 내용은 같다. hyeonkyeong 백엔드는 `label`·`name`·`area`를 모두 읽으므로 앱 동작에는 영향 없다.
- 부등호 기준 변경은 이상·이하 / 초과·미만 해석을 다시 정한 것으로 보인다. 2장 오답 중 부등호 2건과 관련 있을 수 있다.

## 6. 학습·평가 방법

### 학습
- 데이터: `data_fixed4/train_fixed4.jsonl`, `val_fixed4.jsonl` (`test_set.jsonl`은 학습에 쓰지 않고 평가에만 씀)
- 코드: `members/haechan/finetune/train_qlora.py` (data_v6 학습과 같은 코드·설정)
- `--epochs 3 --batch 2 --accum 8 --eval-steps 0`, lr 1e-4, LoRA r32/α64, seed 42
  - 에폭당 461스텝, 총 1,383스텝, 230스텝마다 평가·체크포인트
- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
- 서버 ws6 (RTX 4090 24GB), **2시간 28분**, VRAM 약 18GB
- 환경은 data_v6 학습과 같다(torch 2.11.0+cu128, transformers 4.57.6, peft 0.21.2, bitsandbytes 0.50.2).

### 평가
- `members/haechan/finetune/eval_model.py --data data_fixed4/test_set.jsonl`
- test_set 234문제 = 공식 111(`official111`) + 해찬 58 + 해찬 34 + 해찬 31 (`source` 필드)
- 비교 대상: fx 1·2·3에폭 = `checkpoint-460`·`920`·`1383`, v6 3에폭 = data_v6 `checkpoint-1131`
- 세트별 점수와 "anchors를 앱처럼 채움" 점수는 문제별 결과 jsonl을 다시 읽어 셌다.

## 7. 남은 일

1. fixed-4의 `indicators`만 있는 400개에 `anchors`·`name`·`explain_*`를 채운 다음 버전으로 다시 학습하면 되묻기·거절까지 v6를 넘는지 확인.
2. 부등호 기준(이상/초과 해석)을 팀에서 하나로 정하고 평가 정답과 학습 데이터를 맞추기.
3. 검증 데이터와 train이 겹치는 19문장 확인.
