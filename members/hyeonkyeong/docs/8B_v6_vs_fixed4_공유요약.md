# 8B 학습 결과 공유: data_v6 vs fixed-4 (2026-11-09, hyeonkyeong)

자세한 내용: [8B_fixed4_학습_결과.md](8B_fixed4_학습_결과.md) (이번 비교), [8B_data_v6_재학습_결과.md](8B_data_v6_재학습_결과.md) (v6 재현)

## 한 줄 요약

**fixed-4로 학습한 8B는 v6와 성능이 비슷하고, 강점이 다르다.** 채점기 점수로는 fixed-4가 많이 낮게 나오지만, 감점 대부분은 데이터의 `anchors` 필드 누락 때문이다. 앱 모델은 지금처럼 v6 3에폭을 유지한다.

## 1. 무엇을 했나

- **data_v6**: 해찬 v5와 같은 데이터·같은 설정으로 ws6(4090)에서 다시 학습했다.
  - 데이터는 해찬 스크립트 3개(`build_v5.py` → `gen_aug_v6.py` → `build_v6.py`)로 다시 만들었다.
  - 대화 수(train 5,603 / val 319), 학습 샘플 수(6,028), 라벨 수정 기록(`EDIT_LOG_v6.csv`)이 해찬 기록과 모두 같다.
  - 점수도 v5와 거의 같다(공식 111문제 추출 97.0, v5와 같음).
  - 지금 앱에 붙은 모델이 이 3에폭이다.
- **fixed-4**: yappang 통합 데이터 `q4b-final-data-fixed4-2026-11-09`로 같은 설정으로 학습했다(2시간 28분).
- **비교 방법**: test_set 234문제로 두 모델을 같이 채점했다.
  - 구성: 공식 111 + 해찬 58·34·31문제
  - test_set은 학습에 쓰지 않았다.

## 2. 결과 (fx 3에폭 vs v6 3에폭)

| 항목 | fixed-4 | v6 | 차이 |
|---|---|---|---|
| 추출 전체 일치 (채점기 그대로, 140건) | 82.1 | 93.6 | v6 +16문제 |
| **추출 전체 일치 (anchors를 앱처럼 채움)** | **95.0** | 93.6 | **fixed-4 +2문제** |
| 되묻기 사유 일치 (56건) | 75.0 | 82.1 | v6 +4문제 |
| 되묻기 대상 지표 일치 | 75.0 | 80.4 | v6 +3문제 |
| 거절 정확도 (38건) | 78.9 | 84.2 | v6 +2문제 |
| 되묻기 판단 | 100 | 100 | 같음 |

- 추출은 거의 같고, 되묻기·거절은 v6가 조금 낫다. 모두 몇 문제 차이라서 다시 돌리면 뒤집힐 수 있는 수준이다.
- "anchors 채움"은 공식 채점기가 아니라, 앱 백엔드 동작에 맞춰 다시 센 값이다. 앱 백엔드는 `anchors`가 없으면 사용자 지정 지표 id로 채운다.

## 3. fixed-4 점수가 낮게 나온 이유

- fixed-4가 틀리고 v6가 맞힌 추출 문제 21개를 하나씩 열어봤다.
  - **17개는 지표를 다 맞혔는데 `anchors` 필드만 안 써서 틀린 것**이었다.
  - 나머지는 부등호 2개, 지표 위치 1개, 오타 문장 되묻기 1개다.
- 원인은 **fixed-4에 새로 들어온 추출 정답 400개에 `indicators` 필드만 있고 `anchors`·`name`·`explain_*`가 없는 것**이다.
  - 예: "이자보상배율 6배 이상인 회사만 보여줘"
  - 그래서 모델이 "단순한 문장에는 `indicators`만 쓴다"를 배웠다.
- 같은 입력인데 두 데이터의 정답이 다른 대화도 456개 있다.

| 바뀐 부분 | 개수 | 앱 영향 |
|---|---|---|
| 되묻기 후보 키 `name` → `label` | 363 | 없음 (백엔드가 둘 다 읽음) |
| 부등호 기준 (`> 0` → `>= 0` 등) | 71 | 기준 통일 필요 |
| 안내 문구 | 24 | |

## 4. "v6에 평가 데이터가 섞였다"는 의견 확인

| 확인한 것 | v6 | fixed-4 |
|---|---|---|
| 평가 문장이 학습 데이터에 그대로 있음 | 0 | 0 |
| 거의 같은 문장 (숫자·어미만 다름), 공식 111 중 | 10 | 11 |

- 거의 같은 문장의 예: "PER 12배 이하" ↔ "PER 10배 이하"
- **v6에서 찾은 10개는 전부 fixed-4에도 있다.**
- 해찬 보강 데이터(aug6)는 평가에서 틀린 유형을 보고 만들었다. 다만 평가와 비슷한 문장은 걸러냈다. 이 보강분은 fixed-4에도 들어 있다.
- 결론: **v6만 유리한 섞임은 없다.** 평가를 참고해 데이터를 다듬은 영향은 두 모델에 똑같이 있다.

## 5. 참고

- 두 데이터의 검증(val) 문장은 사실상 같다. fixed-4 val 317문장이 모두 v6 val에 있다.
- val loss는 두 모델 모두 0.0063~0.0065로 비슷했다. val loss만으로는 `anchors` 문제가 드러나지 않았다.
