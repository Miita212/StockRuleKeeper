# 8B data_v6 vs fixed-4, yappang 채점 기준으로 비교 (+ 4B v4) (2026-11-09, hyeonkyeong)

yappang `q4b-v4-evaluation.md`와 **같은 시험·같은 채점기**로 8B 두 모델(data_v6, fixed-4)을 다시 채점했다. 4B v4도 같은 표에 넣었다.
수치는 결과 파일에서 직접 센 **측정값**이고, 원인 설명은 "해석"으로 구분했다.

- 근거
  - 채점기: `members/yappang/train_model_q4b/scripts/eval_q4b.py`의 `report()` 정의(`field_score`, `SLANG_WORDS` 그대로 가져다 씀)
  - 시험: `members/yappang/train_model_q4b/data/test_set.jsonl` (정답 수정 후, `43667ed`)
  - 8B 답: ws6 `runs/eval_fixed4-hyeonkyeong/*.jsonl`
  - 4B v4 답: `members/haechan/q4b-finetune-haechan/results/eval_q4b-v4.jsonl` + `eval_q4b-v4-haechan.jsonl` (111 + 123 = 234)
- 같이 볼 문서: [8B_v6_vs_fixed4_공유요약.md](8B_v6_vs_fixed4_공유요약.md), [8B_fixed4_학습_결과.md](8B_fixed4_학습_결과.md)

## 결론

1. **yappang 기준 완전 일치율은 8B v6 73.9%로 가장 높다.** 8B fixed-4는 67.1%(3에폭), 4B v4는 66.2%다.
2. **완전 일치율은 문구(message) 차이와 `anchors` 누락에 크게 좌우된다.** 거절·되묻기 문구가 정답과 한 글자라도 다르면 틀린다. 그래서 "20개 밖 개념 거절"(B·L)은 모든 모델이 0~1/10이다.
3. 문구를 빼고 **구조만 비교하면 네 모델이 85.0~87.2%로 거의 같다**(6장). yappang 5절이 제안한 "구조 일치 지표"를 같은 방식으로 직접 센 값이다.
4. **4B v4에서도 `anchors` 누락이 17건 나왔다.** 8B fixed-4(18건)와 같다. v6로 학습한 8B는 0건이다. 그래서 fixed-4 데이터의 `indicators`만 있는 정답 400개가 원인이라는 해석이 4B에서도 맞는 것으로 보인다(해석).
5. 앱 모델은 지금처럼 8B v6 3에폭을 유지한다.

## 1. 평가 조건

| 항목 | 8B (v6, fixed-4) | 4B v4 |
|---|---|---|
| 모델 | Qwen3-8B + LoRA (hyeonkyeong 학습, ws6) | Qwen3-4B + LoRA (haechan 학습) |
| 학습 데이터 | v6: train 5,603 / val 319, fixed-4: train 6,942 / val 314 | fixed-4 |
| 학습 설정 | r32 / α64, lr 1e-4, 3에폭, batch 2×8 | r32 / α64, 3에폭 1,383스텝 |
| 생성 | greedy, `enable_thinking=False`, 4bit nf4, 최대 1024토큰 (`haechan/finetune/eval_model.py`) | greedy, `enable_thinking=False`, 4bit nf4, 최대 900토큰 (`eval_q4b.py`) |
| 시험 | `test_set.jsonl` 234문항 | 같음 |
| 채점 | `eval_q4b.py` 정의 그대로, 정답 수정 후 기준 | 같음 |

- 8B 답은 ws6에 있던 **정답 수정 전** test_set으로 생성했다.
- 두 파일의 입력(system·user 메시지)은 234문항 모두 같고, 정답(`output`)만 8건 다르다. 그래서 다시 생성하지 않고, 이미 만든 답을 **수정 후 정답**으로 다시 채점했다.
- 4B v4는 이 방식으로 다시 세어도 yappang 문서 값(정답 수정 후 155/234, 공식 111 88/111)이 그대로 나온다. 채점 재현을 확인한 것이다.
- 8B는 1에폭(fx-1ep)도 채점했지만 모든 항목에서 크게 낮아(완전 일치 37.6%) 표에서 뺐다.

## 5. 완전 일치가 틀린 이유

### 5.1 정답과 형태(최상위 키)가 다른 경우

| 원인 | 8B fx 2에폭 | 8B fx 3에폭 | 8B v6 3에폭 | 4B v4 |
|---|---|---|---|---|
| **추출인데 `anchors`가 빠짐** | 11 | 18 | **0** | 17 |
| 모호 되묻기를 값 되묻기로 답함 (`candidates` 대신 `indicator_id`·`options`) | 11 | 10 | 5 | 11 |
| 값 되묻기를 모호 되묻기로 답함 | 3 | 4 | 5 | 4 |
| 거절해야 하는데 되묻기 | 5 | 6 | 6 | 7 |
| 거절해야 하는데 추출 | 0 | 2 | 0 | 0 |
| 추출해야 하는데 되묻기 | 1 | 1 | 0 | 0 |
| 기타 (`known` 빠짐, 되묻기를 거절로) | 1 | 0 | 1 | 2 |
| **합 (형태 불일치)** | 33 | 42 | **17** | 42 |

- `anchors` 누락은 fixed-4로 학습한 모델에만 있다(8B·4B 모두). v6로 학습한 8B는 0건이다.
- 해석: fixed-4 학습 데이터에 새로 들어온 추출 정답 400개에 `indicators`만 있고 `anchors`가 없어서다. 자세한 내용은 [8B_fixed4_학습_결과.md](8B_fixed4_학습_결과.md) 3장.

### 5.2 형태는 같은데 내용이 다른 경우

| 다른 키 | 8B fx 3에폭 | 8B v6 3에폭 |
|---|---|---|
| `message`만 (거절·되묻기 문구) | 20 | 25 |
| `candidates` + `message` | 7 | 7 |
| `indicators` (지표 값) | 6 | 9 |
| `candidates`만 | 2 | 2 |

- 형태가 맞은 오답의 대부분은 **문구만 다른 경우**다.
- 예 (B 20개 밖 개념 거절, "코스닥 종목만 보여줘")
  - 정답: "상장 시장 구분은 아직 쓰지 않는 지표예요. 시가총액이나 20일 평균 거래대금으로 볼 수 있어요."
  - 8B v6: "코스닥은 거래소가 아니라 시장 구분이에요. 거래소별로 볼 수 있어요."
  - 거절 판단은 맞았지만 문구가 달라서 완전 일치에서 틀렸다. B·L이 모든 모델에서 0~1/10인 이유다.

## 6. 구조 일치 (문구 차이를 뺀 비교)

yappang 문서 5절의 제안("되묻기 이유 + 후보 id 집합, 거절 여부로 구조 일치를 보고 문구 차이와 모델 오류를 분리")을 아래 정의로 직접 셌다.

- 거절: 정답이 거절이고 모델도 거절하면 맞음 (문구는 보지 않음)
- 되묻기: 이유(`reason`)와 대상 지표 id 집합(`candidates`의 id, 또는 `indicator_id`)이 같으면 맞음
- 추출: 20개 지표 설정(`indicators`)이 모두 같고, `anchors`가 같으면 맞음. `anchors`가 없으면 사용자 지정 지표 id로 채운다. hyeonkyeong 앱 백엔드도 이렇게 채운다.

| | 전체 (234) | 추출 (140) | 되묻기 (56) | 거절 (38) |
|---|---|---|---|---|
| 8B fx 2에폭 | 85.5% (200) | 94.3% (132) | 62.5% (35) | **86.8% (33)** |
| 8B fx 3에폭 | 86.3% (202) | **95.0% (133)** | 69.6% (39) | 78.9% (30) |
| **8B v6 3에폭** | **87.2% (204)** | 93.6% (131) | **73.2% (41)** | 84.2% (32) |
| 4B v4 | 85.0% (199) | 94.3% (132) | 66.1% (37) | 78.9% (30) |

| 출처별 구조 일치 | official111 | haechan58 | haechan31 | haechan34 |
|---|---|---|---|---|
| 8B fx 2에폭 | 89.2% (99) | **87.9% (51)** | 77.4% (24) | 76.5% (26) |

- 구조로 보면 네 모델 차이는 전체 234문항 중 최대 5문항이다.
- 남은 차이는 되묻기다. 8B v6가 가장 높고(73.2%), 4B v4가 그다음이다(66.1%). 대부분 "모호 되묻기 ↔ 값 되묻기" 혼동이다(5.1 표).
- haechan34(새 문장)에서 4B v4는 73.5%로, 완전 일치(35.3%)보다 훨씬 높다. yappang 문서의 "새 문장 일반화 약함"은 상당 부분 문구 차이 때문으로 보인다(해석).

## 7. 정리 (yappang 문서 4·5절과 연결)

| yappang 문서의 문제점 | 8B 결과로 본 것 |
|---|---|
| 1. 지표 모호 되묻기 2/9 | 8B도 약하다(v6 0/9, fx 3에폭 3/9). 모델 크기보다 데이터 쪽 문제로 보인다(해석). |
| 2. 값 되묻기 14/18 | 8B 15~16/18. 모호 ↔ 값 혼동은 네 모델 모두 있다. |
| 3. 20개 밖 개념 거절 | 완전 일치는 모두 0~1/10이지만, 거절 판단 자체는 78.9~86.8%가 맞는다. 낮은 점수의 대부분은 문구 차이다. |
| 4. 새 문장 일반화 약함 (haechan34) | 구조로 보면 73.5~82.4%. 문구 차이를 빼면 격차가 줄어든다. |
| 5. 문구만 다른 오답 | 8B에서도 같다. 형태가 맞은 오답의 대부분이 `message` 차이다. |
| (새로 찾음) `anchors` 누락 | fixed-4로 학습한 8B·4B 모두 17~18건. fixed-5에서 400개 보강 필요. |

**fixed-5 초안(`docs/fixed5-draft.md`)에 더하면 좋을 것**
- fixed-4의 `indicators`만 있는 추출 정답 400개에 `anchors`(사용자 지정 지표 id)·`name`·`explain_*`를 채운다.
- 평가에 6장의 구조 일치 지표를 같이 낸다. 그래야 완전 일치만으로 모델을 판단하지 않는다.

## 8. 아직 확인하지 않은 것

- 8B를 정답 수정 후 test_set으로 **다시 생성**한 결과. 이번에는 입력이 같아서 이미 만든 답을 다시 채점했다. 생성 결과는 같을 것으로 본다.
- 8B와 4B의 최대 토큰(1024 vs 900) 차이의 영향. 잘린 답(JSON 오류)은 두 쪽 모두 0건이라 영향은 작을 것으로 본다.
- haechan31에서 v6가 높은 것이 aug6 보강과 관련 있는지.
- 구조 일치 정의는 hyeonkyeong이 정한 것이다. 팀 정의가 따로 생기면 맞춰야 한다.
