## 2. 출력 형식

```
{"symbol": "005930", "name": "삼성전자", "period_months": 3,
 "indicators": {1: {"id", "name", "value", "unit", "as_of", "status", "note"}, ... 20: {...}}}
```

| 필드 | 의미 |
|------|------|
| value | 숫자 또는 `None`. `None`은 **계산 불가**이며 미충족이 아님 |
| unit | `%` / `배` / `년` / `억원` (금액 지표 5, 14, 19는 억원으로 변환된 값) |
| status | `ok` / `unavailable` / `적자 전환` 등 사유 |
| note | 계산 불가 사유(error) 또는 주의(warn) |
| as_of | 계산 기준(보고서 기준일 또는 가격 기준일) 설명 문자열 |

## 3. 우리 백엔드가 받을 때 주의 (단위)

- 백엔드 `master.json`의 `scale`은 금액 지표를 원 단위 기준으로 곱한다 (5, 19: 1e8, 14: 1e12).
- 이 모듈의 value는 이미 억원이라서 **그대로 넣으면 판정이 틀린다**. 받는 쪽에서 `value × 1e8`(원)으로 되돌려 넣는다.

## 4. 합의가 필요한 질문

1. 금액을 억원(현재)으로 둘지, 원 단위로 바꿀지. (제안: 현재대로 억원 유지, 받는 쪽에서 변환)
2. 지표 6(연속 영업흑자 연수)·13(연속 배당 연수)의 조회 한도 도달 여부(`at_least`)를 출력에 포함할지. (제안: `note` 또는 별도 필드로 포함. 지금은 `run.py`에서 사라짐)
3. 금융비용이 0 이하로 나오는 경우(한미반도체 등)의 지표 3 처리. (2026-11-05 우리 백엔드 결정: 금융비용은 부호와 상관없이 크기로 읽고, 12개월 합이 0 이하면 직전 사업연도 값을 쓴다. 원인은 환율손실 되돌림과 음수 기재였다. 이 모듈은 아직 계산 불가로 처리하므로, 같은 기준으로 맞출지 논의 필요)
4. 지표 10·11(PER/PBR)은 KIS 제공값(직전 결산 EPS/BPS) 기준임을 문서에 명시. (제안: `as_of`에 이미 표시되므로 문서에 한 줄 추가)
5. 우리 백엔드(`calc_financial.py`)의 지표 3·9 계산 기준 통일. (2026-11-05 완료: 지표 3은 상각비 포함 EBITDA로, 지표 9는 전년 흑자·당기 0 이상일 때만 계산하도록 이 모듈과 같은 기준으로 맞췄다)
