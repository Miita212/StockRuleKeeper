# 리포트 톤 가이드 (H8)

> 작성: hyeonkyeong / 2026-11-04 / 상태: **제안 (팀 확인 전)**
> 용도: 종합 리포트(S8) 문장 규칙. S-5(byungjun)의 리포트 서술 생성과 V-1 검증(V7·V8)이 이 문서를 기준으로 한다.
> 기본 말투는 `tone_safety_guide.md`(H6)의 해요체를 따른다.

## 1. 한 줄 원칙
**숫자는 코드가 계산해서 입력으로 주고, 모델은 그 숫자로 문장만 쓴다. 이유를 단정하지 않고, 미래를 말하지 않고, 사라는 말을 하지 않는다.**

## 2. 리포트 구성 (모델이 쓰는 3블록)
예시 E18 기준. 주의 문구와 "스스로 판단해 보세요" 질문은 템플릿이라 모델이 쓰지 않는다.

| 블록 | 내용 | 길이 |
| --- | --- | --- |
| 제목 | 이번 변경의 핵심 한 줄 | 1문장 |
| 변경 요약 | 무엇을 어떻게 바꿨는지 (before → after, 잠근 지표) | 1~2문장 |
| 종목 변화 | 조건을 바꾸니 종목 수·하락 폭이 어떻게 달라졌는지 | 1~2문장 |

## 3. 문장 규칙

| # | 규칙 | 설명 |
| --- | --- | --- |
| 1 | **입력에 있는 숫자만** 쓴다 | 문장 속 숫자와 종목명이 입력 JSON과 한 글자라도 다르면 폐기 (V8). 계산하지 말고 입력의 값을 그대로 옮긴다. |
| 2 | **원인을 단정하지 않는다** | "~해서 줄었어요"가 아니라 "~했더니 ~로 나타났어요". 같이 일어난 일과 원인은 다르다. |
| 3 | **미래·예측을 쓰지 않는다** | "앞으로 ~할 거예요", "~로 이어질 수 있어요"(근거 없이)는 금지. 과거 기간의 결과만 말한다. |
| 4 | **매수·매도 권유를 하지 않는다** | "이 기준이 더 좋아요", "이 종목을 담아 보세요" 금지. 선택은 사용자 몫이다. |
| 5 | **표본이 적으면 알려 준다** | 종목 수가 입력의 `count`가 작거나 비교 기간이 짧으면 "종목 수가 적어서 참고만 해 주세요"를 붙인다. |
| 6 | **이 데이터의 한계를 말한다** | 모르는 것은 "이 데이터로는 이유까지는 알 수 없어요"라고 쓴다. |
| 7 | 좋다·나쁘다 대신 **바뀐 정도**를 쓴다 | "줄었어요 / 늘었어요 / 그대로예요" |
| 8 | 잠근 지표는 **그대로임을** 한 번 말한다 | "연속 영업흑자 연수는 잠가 두어서 그대로예요." |

### 표본이 적다고 볼 기준 `[제안]`
- 변경 후 종목 수(`count.after`)가 **10개 미만**이면 표본 경고 문장을 붙인다.
- 정확한 기준은 팀이 정한다. 입력에 `count`가 없으면 종목 수 문장을 쓰지 않는다.

## 4. 허용 문장 예시 (이렇게 쓴다)

| # | 상황 | 허용 문장 |
| --- | --- | --- |
| A1 | 제목 | "빚 기준을 엄격하게 하니 종목이 줄고, 하락 폭도 줄었어요" |
| A2 | 변경 요약 | "빚 비율(부채비율) 기준을 100% 이하에서 80% 이하로 더 엄격하게 바꿨어요." |
| A3 | 잠금 | "연속 영업흑자 연수는 잠가 두어서 그대로예요." |
| A4 | 종목 변화 | "조건에 맞는 종목이 18개에서 11개로 줄었어요." |
| A5 | 한계 | "이 데이터로는 이유까지는 알 수 없어요." |
| A6 | 같이 나타난 일 | "기준을 바꾼 기간에 하락 폭도 함께 줄어든 것으로 나타났어요." |
| A7 | 표본 경고 | "종목 수가 적어서 참고만 해 주세요." |
| A8 | 변화 없음 | "이번 변경으로 조건에 맞는 종목 수는 그대로예요." |

## 5. 금지 문장 예시 (이렇게 쓰지 않는다)

| # | 금지 문장 | 왜 안 되나 | 고치면 |
| --- | --- | --- | --- |
| B1 | "빚 기준을 낮춰서 하락 폭이 줄었어요." | 원인 단정 | "빚 기준을 낮췄더니 하락 폭이 줄어든 것으로 나타났어요." |
| B2 | "앞으로도 이 기준이면 덜 떨어질 거예요." | 예측 | "이 기간에는 하락 폭이 줄었어요." |
| B3 | "이 원칙으로 투자하면 수익이 나요." | 보장 | (쓰지 않는다) |
| B4 | "이제 이 11개 종목을 사 보세요." | 매수 권유 | "조건에 맞는 종목이 11개예요." |
| B5 | "종목이 12개로 줄었어요." (입력은 11개) | 숫자 불일치 (V8) | "종목이 11개로 줄었어요." |
| B6 | "이 기준이 훨씬 더 좋은 선택이에요." | 평가·권유 | "기준이 더 엄격해졌어요." |
| B7 | "업종 평균보다 빚이 적어서 안전해요." | 입력에 없는 사실, 보장 | (쓰지 않는다) |
| B8 | "시장이 안 좋아서 종목이 줄었어요." | 입력에 없는 원인 | "이 데이터로는 이유까지는 알 수 없어요." |

## 6. 입력 JSON (E18) 필드와 문장 대응

```json
{"period":"3개월","principle":"빚 적은 우량주 원칙",
 "diff":[{"name":"부채비율","before":100,"after":80,"unit":"%"}],
 "locked":["연속 영업흑자 연수"],"count":{"before":18,"after":11}}
```

| 입력 필드 | 쓰는 문장 |
| --- | --- |
| `diff[].name/before/after/unit` | 변경 요약 (A2) |
| `locked[]` | 잠금 문장 (A3) |
| `count.before/after` | 종목 변화 (A4) |
| `period` | "3개월 동안" 같은 기간 표현 |
| `principle` | 제목·요약에서 원칙 이름을 부를 때만 사용 |

- 입력에 없는 필드를 상상해서 쓰지 않는다 (예: 수익률, 업종 평균).

## 7. 검수 체크리스트
- [ ] 문장 속 숫자·지표 이름·종목명이 입력과 모두 같은가 (V8)
- [ ] 원인 단정 표현("~해서", "~때문에")이 없는가
- [ ] 미래 표현이 없는가
- [ ] 매수·매도 권유가 없는가
- [ ] 종목 수가 10개 미만이면 표본 경고가 있는가
- [ ] 잠근 지표가 있으면 "그대로"라고 말했는가

## 8. 팀 확인이 필요한 항목
1. 표본 경고 기준(종목 10개 미만) — byungjun(S-5)과 확인
2. 리포트 입력 JSON의 `count` 외 필드(하락 폭 등)를 쓸지 — 화면 13 구현 범위에 달려 있음
3. "~로 나타났어요" 같은 완곡 표현을 V7/V8에서 어떻게 볼지 (현재 금지 패턴에는 없음)
