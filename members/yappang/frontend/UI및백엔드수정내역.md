## 2. 대화로 정한 지표를 "해당 지표"로 따로 표시

- **목적**: 02 원칙 세팅에서 20개 지표가 정해진 순서로 전부 나열되어, 방금 대화로 어떤 지표를 어떤 값으로 정했는지 알기 어려웠다. 대화로 정한 지표를 맨 위에 따로 보여준다.
- **기준**: 서버가 내려주는 지표별 `source` 값. `user`·`inferred`는 대화로 정한 지표, `default`는 기본값 지표다. 백엔드 수정은 없다.
- **Figma**: "UI 병준 수정본" 페이지의 02 원칙 세팅 화면 4종(02, 02-2, 02 기존 사용자 · 5단 바, 02 로딩 시안)에 반영했다.

### 화면 구성 (`src/screens/S02_PrincipleSetup.tsx`)

1. **해당 지표 · n개** 구역이 맨 위에 나온다. 파란 테두리 카드로 표시한다.
2. **그 외 지표 · m개** 구역이 그 아래에 나온다. 기존 카테고리별 순서는 유지하고, 값 글자색만 연한 회색으로 한다. 안내 문구는 "기본값이에요. 종목 조건에는 넣지 않아요".
3. 해당 지표가 0개이면 두 구역 제목을 모두 숨기고 예전처럼 카테고리별로만 보여준다. 기본값 지표가 0개이면 "그 외 지표" 제목만 숨긴다.

### 수정 흐름(02-2)에서 "방금 바꾼 지표" 강조

- "해당 지표"에는 정해진 지표 전체를 보여주되, 그중 방금 바꾼 지표는 맨 위에 따로 강조한다.
  - 방금 바꾼 지표: 파란 테두리와 연한 파란 배경, "방금 바꿨어요" 표시, 바꾸기 전 값("이전 150% 이하")을 취소선으로 함께 표시한다.
  - 이전부터 정해 둔 지표: 연한 테두리로 보여준다.
- 방금 바꾼 지표의 기준은 저장된 원칙과 비교해서 정한다. 값이 달라졌거나, 기본값이던 지표를 새로 정한 경우다. 저장 전까지 여러 번 대화로 고쳐도 저장된 원칙 대비 달라진 지표 전체가 표시된다.

## 3. 기본값 지표를 원칙에 포함할지 고르는 스위치

- **목적**: 지금까지는 대화로 정하지 않은 지표도 기본값으로 채워져 항상 20개 지표가 원칙에 들어갔다. 사용자가 기본값 지표를 원칙에 담을지 말지 고르게 한다.
  - 포함(ON, 기본): 20개 전체가 원칙에 들어간다. 이전과 같은 동작이다.
  - 제외(OFF): 대화로 정한 지표(`source`가 `user`·`inferred`)만 n개로 원칙에 들어간다. 판정서, 종목 목록의 충족 개수(`원칙 14/n개 충족`), 시뮬레이션도 n개 기준이 된다.
- **Figma**: "UI 병준 수정본" 페이지의 02 원칙 세팅 화면 4종에 스위치(ON 상태)를 넣었고, OFF 상태 시안 1장("02 원칙 세팅 · 기본값 지표 제외 (토글 OFF)")을 맨 아래 행에 따로 두었다.

### 화면 구성 (`src/screens/S02_PrincipleSetup.tsx`)

- "그 외 지표 · m개" 구역 제목 오른쪽에 **"원칙에 포함" 스위치**가 있다. 안내 문구는 ON일 때 "원칙에 함께 담을까요?", OFF일 때 "원칙에 담지 않아요. 판정서에도 안 나와요".
- OFF이면 기본값 지표 카드와 카테고리 제목이 흐려지고 잠금 버튼을 누를 수 없다.
- 해당 지표가 0개이거나 기본값 지표가 0개이면 이 구역(스위치 포함)이 보이지 않는다.
- 스위치 초기값: 새 원칙은 ON. 저장된 원칙을 고치는 중(02-2)이면 그 원칙이 `source: "default"` 지표를 담고 있었는지로 정한다. 담고 있으면 ON, n개만 담고 있으면 OFF.
- 스위치를 꺼도 화면의 초안(`draft`)에는 20개가 그대로 있다. 대화로 수정할 때 서버에 20개를 모두 보낸다. 저장(`approve()`)할 때만 OFF이면 `source`가 `default`인 지표를 빼고 보낸다.
- 02-2에서 저장하면 "원칙 수정 완료"(S14)에 보이는 변경 목록은 저장하는 지표 중 값이 달라진 것만 보여준다. 이전 원칙에 없던 기본값 지표는 제외하고, 새로 정한 지표는 이전 값을 "없음"으로 표시한다.

### 변경 파일

**[백엔드 ⚠️]**

- `backend/services/principles.py` 의 `normalize()`: 기본값 지표를 뺀 n개짜리 원칙을 `base`로 받으면 `current[ok["id"]]`에서 `KeyError`가 났다. `base`에 없는 지표를 대화로 새로 정하는 경우다. 그래서 기본값 20개(`default_indicators()`)를 먼저 깔고 그 위에 `base`를 덮어쓰도록 바꿨다. 이제 응답의 `indicators`는 항상 20개이고, `base`에 없던 지표는 `source: "default"`로 채워진다.
  - 그 외 백엔드 코드는 바꾸지 않았다. 원칙 저장(`save`, `new_version`)은 받은 지표 목록을 그대로 저장하고, 판정(`judge_stock`), 종목 목록(`stock_card`), `core_ids`는 지표 개수에 상관없이 동작한다.

**[프론트]**

- `src/screens/S02_PrincipleSetup.tsx`: `includeDefaults` 상태, 스위치 UI, 저장할 때 기본값 지표 제외, S14에 넘길 변경 목록 계산 수정.
- `src/components/IndicatorCard.tsx`: `mark`에 `"off"` 값 추가(흐리게 표시).
- `src/App.css`: 스위치(`.switch`, `.switch-box`), 흐린 카드(`.mark-off`, `.category.off`), 구역 제목 배치(`.zone.rest`) 스타일 추가.

### 알려진 한계

- 브라우저에서 화면으로 확인하지 않았다. 프론트는 타입 검사(`tsc`)와 eslint만 통과했고, 백엔드는 `normalize()`를 DB 없이 단독으로 호출해 `base`가 1개짜리여도 `KeyError` 없이 20개를 돌려주는 것만 확인했다.
- 실행 중인 백엔드 서버는 다시 시작해야 `normalize()` 수정이 반영된다.
- 원칙을 OFF로 저장한 뒤 다시 ON으로 바꿔 저장하는 경우(02-2)는, 이전에 없던 기본값 지표 17개가 새로 들어가지만 S14 변경 목록에는 나오지 않는다.

## 4. 08 원칙 수정하기에 기존 원칙의 지표 목록 추가

> ⚠️ 10번에서 이 목록은 08 화면에서 빠지고 **"내가 설정한 지표값 상세보기" 버튼을 누르면 올라오는 시트**로 옮겨졌다. 아래의 "3개만 보이고 펼치기", "나머지 n개 보기" 설명은 더 이상 없다(시트에는 전체가 스크롤로 보인다). 지표 정렬·"내가 정한 지표/기본값" 구분·자물쇠·잠금 서버 전달 수정은 그대로다. 현재 동작은 10번을 본다.

## 5. 지표 수치를 눌러 직접 입력

- **목적**: 수치를 대화나 +/− 로만 바꿀 수 있어서, 원하는 값(예: 부채비율 120%)을 바로 넣기 어려웠다. 수치를 누르면 숫자를 직접 입력할 수 있게 한다.

### 동작

- 수치가 **회색 둥근 박스**로 보이고, 누르면 숫자 입력칸으로 바뀐다. 단위와 방향 말(`% 이하`)은 입력칸 옆에 그대로 붙어 있다.

## 7. 06 원칙 리스트: 하단 바 가림 오류 수정과 5개씩 페이지

> 8번에서 페이지 크기가 5개 → **4개**로 바뀌었다. 아래의 "5개"는 7번 당시 값이다.

- **문제**: 원칙이 많으면 카드가 하단 메뉴 바 위로 겹쳐 보였다.
- **원인**: 6번에서 카드에 `position: relative; z-index: 1`(밀어서 삭제 버튼 아래로 깔기 위해)을 줬는데, 하단 바(`.nav`)는 `z-index`가 없어서 카드가 바보다 앞에 그려졌다. 바는 `.content` 바깥의 형제 요소라 `.content`가 스크롤돼도 카드가 바 위로 올라왔다.
- **해결**: `.nav`에 `z-index: 10`을 줘서 하단 바가 항상 맨 앞에 오고, 스크롤되는 카드는 그 뒤로 가려진다. 5단 바를 쓰는 다른 화면도 같은 바라 함께 적용된다. 3단 바(`NavSim`)도 같은 `.nav` 클래스를 쓴다.
- **Figma**: "UI 병준 수정본" 페이지 맨 아래 행(y=8700)의 "06 원칙 리스트 · 다른 원칙 7개 (1/2 페이지)", "(2/2 페이지)".
- **페이지 규칙**: "내가 만든 다른 원칙"이 **5개를 넘으면** 5개씩 페이지로 나눈다. 현재 적용 중인 원칙은 항상 맨 위에 고정이고 페이지에 포함하지 않는다. 5개 이하이면 페이지 이동 표시는 나오지 않는다.

### 동작

- 이름이 표시 영역보다 **길 때만** 움직인다. 짧으면 그대로 있다.

- 이름을 고치는 중(입력칸)에는 적용되지 않는다.

## 15. 지표 비활성화 (꾹 눌러 / 말로)

- **목적**: 대화로 정해진 지표를 빼고 싶을 때 쓸 방법이 없었다. 정한 지표를 **비활성화**(= 기본값으로 되돌려 "그 외 지표"로 보냄)할 수 있게 한다.
- **Figma**: "UI 병준 수정본" 페이지 맨 아래 행(y=13700)의 "15-1 지표를 꾹 누르는 중", "15-2 비활성화 확인 창", "15-3 비활성화 후", "15-4 말로 비활성화", "15-5 원칙 수정 · 비활성화 후", "15-6 지표값 상세 시트 · 꾹 눌러 비활성화 확인 창".
- **대상 화면**: 원칙 만들기·고치기 대화 화면(02·02-2·5단 바 버전)의 지표 카드, 그리고 **원칙 관리 → 원칙 수정 → "내가 설정한 지표값 상세보기" 시트**의 지표 카드.

### 동작

- **꾹 누르기**: 정한 지표 카드(대화로 정한 지표 = 해당 지표, 고치기에서는 바뀐 지표와 "그 외 지표"를 펼쳤을 때 보이는 이전에 정한 지표, 시트에서는 "내가 정한 지표")를 **600ms 이상** 누르고 있으면 확인 창이 뜬다: **"지표를 비활성화 하시겠습니까?"** / "부채비율 지표를 '그 외 지표'로 옮기고 기본값으로 되돌려요." / 취소·**비활성화**(빨강). 기본값 지표 카드는 꾹 눌러도 아무 일도 없다. 손가락이 10px 넘게 움직이면 취소하고, 꾹 누른 뒤 이어지는 클릭(수치 입력 등)은 막는다.
- **비활성화**를 누르면 그 지표가 **기본값**(연산자·값·단위)으로 돌아가 `source: "default"`가 되고 자물쇠도 풀리며, **"그 외 지표"** 쪽으로 옮겨진다. 대화에는 "○○ 지표를 비활성화했어요" 말풍선과 "부채비율 100% 이하 → 100% 이하 (기본값)" 한 줄 요약이 쌓이고 지표 카드가 새로 나온다(바뀐 값이 "그 외 지표"로 이동한 모습).
- **입력창에 말로 해도 같다**: "○○는 사용하고 싶지 않아", "○○ 버려줘", "○○ 삭제해줘", "○○는 비활성화해줘" 같은 말을 입력하면 모델에 보내지 않고 **같은 확인 창**이 뜬다(`src/data/deactivate.ts`). 한 번에 여러 지표를 말해도 된다("부채비율이랑 PER 삭제해줘" → 한 창에서 같이 비활성화). 이때 취소하면 "그대로 둘게요" 말풍선이 나온다.
  - 지표 이름과 자주 쓰는 말(PER, PBR, EBITDA, 시총, 배당수익률 등)을 알아본다. 긴 이름이 먼저 잡혀서 "영업이익 증가율"이 "영업이익"으로 오인되지 않는다.
  - "빚 많은 회사는 제외할래요"처럼 조건을 정하는 말은 해당 표현이 없어서 지금처럼 모델이 처리한다(`제외`, `빼`는 일부러 넣지 않았다).
  - 이미 기본값인 지표를 말하면 "이미 기본값(그 외 지표)이에요", **잠근 지표**를 말하면 "잠겨 있어서 비활성화할 수 없어요. 잠금을 풀고 다시 말씀해 주세요"라고 답한다. 꾹 눌러 비활성화하는 것은 잠금과 상관없이 된다(수치 직접 입력과 같은 방식).
  - 정한 지표가 아직 없는 처음 말(새 원칙의 첫 입력)이나 되묻기에 답하는 중에는 이 규칙을 쓰지 않는다.
- 08 시트에서 비활성화하면 시트가 닫히고 대화 화면으로 바뀌어 "이렇게 바뀌었어요!" 카드가 나온다(수치 직접 입력과 같음). 저장은 "이대로 수정할래요"로 한다.
- **저장 때**: 비활성화한 지표는 기본값 지표가 되므로 "원칙에 포함" 스위치를 끄면 원칙에서 빠지고, 켜져 있으면 기본값으로 함께 저장된다(기존 규칙 그대로). 14 화면(수정 완료)의 변경 내용에도 "(이전 값) → (기본값)"으로 나온다.

### 15-2. 후속 수정: 원칙 수정에서 비활성화하면 "바뀐 지표 0개 / 그 외 n개"로 나오던 오류

  - **"03 종목 검색 (Home) · 공지사항 없는 버전 (현재 코드가 쓰는 버전)"**: 원래 03 시안 위치(y=700)이며 띠가 없다. **지금 코드가 쓰는 버전이다**(`S03_StockSearch.tsx`에는 공지 띠가 없다).
  - **"03 종목 검색 (Home) · 공지사항 있는 버전 (나중에 전환용)"**: 같은 줄 오른쪽 끝(x=2820)에 두었고 맨 위에 공지 띠가 있다.
  - 로딩 화면도 같은 방식이다: "03 종목 검색 · 로딩 (최신 값 불러오는 중) · 공지사항 없는 버전 (현재)"와 로딩 시안 줄 오른쪽 끝(x=3760)의 "… 공지사항 있는 버전 (나중에 전환용)".
  - 17-1~17-3(공지 문구가 이동하는 세 장, y=15700)은 "공지사항 있는 버전"의 움직임 설명용이다.
- **코드와의 관계**: 공지 띠는 코드에 아직 없고 지금 화면은 "공지사항 없는 버전"이다. 나중에 띠를 코드에 넣을 때는 켜고 끄는 값을 하나 두고 두 버전을 오가도록 하면 된다.
