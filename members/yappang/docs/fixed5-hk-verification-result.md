# fixed5-hk 데이터 검증 결과

작성: 2026-11-09, yappang. 대상: `train_model_q4b/fixed5-hk-data-2026-11-09`(hyeonkyeong, fixed-4 기반 수정본).
방법: README의 숫자를 데이터로 다시 세고, `data/scripts/check_new_data.py`로 신규·변경분을 검사했다.
기준 문서: `fixed5-draft.md`(개선안 A~E), `fixed5-verification-checklist.md`.
수치는 직접 센 측정값이고, 판단은 "해석"으로 구분했다. 학습은 하지 않았다.

## 1. 결론

- 데이터 자체는 건강하다. 해시·건수·형식·`anchors` 모두 맞고, 학습·검증과 시험 사이 동일 문장은 0건이다.
- 오류는 **홀드아웃 시험 1문항이 학습 보강 문장과 사실상 같은 것** 하나다(아래 3절).
- 제가 제안한 개선안 중 **E(`anchors`)는 완료, 나머지(대조쌍·20개 안 이름 오판 방지·메시지 통일·`name`/`explain`)는 일부만 또는 반영되지 않았다**(4절).
- 지표 모호 2/9(v4)를 올리려면 시험 정답과 학습이 어긋난 표현의 기준을 먼저 정해야 한다(5절).

## 3. 오류·문제

| # | 내용 | 심각도 |
|---|---|---|
| 1 | **홀드아웃과 학습 보강 문장이 거의 같음.** 학습 "회사 순자산보다 싸게 거래되는 주식"(PBR 값 되묻기) ↔ 새 시험 "순자산보다 싸게 팔리는 주식"(같은 정답). 유사도 0.74로 hk 기준(0.75)을 간신히 피했다 | 중: 해당 문항 점수가 부풀 수 있음. 한쪽 교체 필요 |
| 2 | **`name`·`explain_*`는 채워지지 않음.** 추출 답 2,479개 모두 `name`이 비어 있고 `explain_bubble`은 2,139개가 비어 있음. 400건만의 문제가 아니라 기존 데이터 전체의 상태 | 낮음: 앱은 `name`이 없으면 "내 원칙"을 쓴다(`principles.py:114`) |
| 3 | "싸다" 후보가 [10,11] 98건과 [10,11,16] 19건으로 아직 2종 | 확인: README에 "가성비·가격 매력은 시험 정답이 [10,11,16]이라 일부러 뺐다"고 밝힘. 팀이 정할 일 |
| 4 | 학습과 시험 정답이 어긋난 표현이 그대로 남음(5절) | 중: 지표 모호 점수에 직접 영향 |

참고: 검증 중 제 스크립트가 정상 문장("차입금의존도나", "연수나")을 조사 오류로 잘못 잡아서 정규식을 고쳤다. 고친 뒤 신규 123건·홀드아웃 30건은 모두 통과한다.

| 제 개선안 | 반영 | 비고 |

| 후보 집합 통일 | 일부 | "싸다"만 |

## 5. 지표 모호 개선에 영향이 큰 미결 사항

README 6절의 "바꾸지 않은 것"이 핵심이다. 학습과 시험 정답이 서로 다르다.

| 표현 | 학습 데이터 | 시험 정답 |
|---|---|---|
| 이익이 늘어나는 | 값 9 (영업이익 증가율) 56건 | 모호 [8, 9] |
| 폭락·급락·푹 꺼진 | 모호 [15,16] 18건 | 기간 되묻기 [15] |
| 출렁·요동 | 값 18 14건 | 모호 [16,18] |
| 규모가 큰 | 모호 [14,19] | "몸집 큰"은 값 14 (시험 안에서도 갈림) |
| 가성비·가격 매력 | 없음 | 모호 [10,11,16] |

v4가 틀린 "이익이 늘어나는 회사"가 첫 줄과 같은 경우다. 기준을 정하기 전에는 이 데이터로 학습해도 같은 오답이 반복될 가능성이 크다(해석).

## 7. 이번 검증에서 추가한 도구

`data/scripts/check_new_data.py`에 시험 유사 문장 검사(항목 9)를 넣었다. 유사도 0.75 이상이면 실패, 0.65 이상이면 경고, 정답 유형까지 같으면 "정답 같음"을 표시한다. hk 신규 123건에서는 실패 0건, 경고 8건이었고, 3절 1번 문장이 0.74로 경고에 잡힌다. 한계: 시험 세트와만 비교하며, 기존 학습 데이터와는 동일 문장만 검사한다.
