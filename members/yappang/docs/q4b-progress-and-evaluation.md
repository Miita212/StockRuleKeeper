## 4. 현재 시점의 최종 평가

**잘 된 것**
- 필드 정확도가 63.7 → 78.8 → 90.0%로 올라 목표를 달성했다. 원인은 데이터 품질 개선(부등호·조사 수정, 약한 유형 보강)으로 보인다(해석).
- JSON 유효율 100%, 되묻기 "해야 하는지" 판단은 안정적이다.
- 은어 변환율 85.7%로 목표 90%에 근접했다.
- 8GB 노트북에서 학습·구동이 가능하다는 점이 입증됐다.

**부족한 것**
- 완전 일치율은 +2.7%p(63.1 → 65.8%)로 개선 폭이 작다.
- v3에서 **되묻기(값 없음)가 17/18 → 12/18로 후퇴**했다. 지표 모호 되묻기를 430 → 1,176건으로 늘린 부작용으로 보인다(**가설, 데이터 확인 전**).
- 지표 모호 되묻기는 2/9로 목표(5/9)에 한참 못 미친다.
- 같은 8B 시험 기준으로 Q4B(v1)는 8B보다 크게 낮다. 새 문장 일반화가 약하다. 이 격차가 v3에서 얼마나 줄었는지는 아직 재지 않았다.
- 15~18번(주가 지표) 혼동, 부정·제외 표현에서 연산자·번호 오류, "영업이익 흑자"를 거절하는 오류가 남아 있다.

**v3 오답 38건의 원인 분류** (`q4b-v4-plan.md` 1절, 문항당 하나로 배정)

| 원인 | 건수 | 성격 |
|---|---|---|
| A. 값 되묻기 ↔ 지표 되묻기 혼동 | 11 | 모델 문제 |
| B. 지표 모호 메시지 문구 불일치 | 3 | 데이터 문제 |
| C. 거절 문구 불일치 | 8 | 채점 문제가 큼(정답 문구에 조사 오류: "매출순이익률나", "EPS 증가율는") |
| D. 단일 지표 번호·값 오류 | 7 | 모델 문제 |
| E. 지표 누락·거절 오판 | 3 | 모델 문제 |
| F. 안내 문구만 다름 | 4 | 채점 문제 가능성 |
| G. 복수·기타 | 2 | 채점·데이터 정의 문제 |

C·F·G(최대 14건)는 구조는 맞고 문구만 다른 경우가 섞여 있어, 실제 모델 능력은 완전 일치율보다 높을 가능성이 있다(해석, 정확한 건수는 구조 일치율 지표로 확인해야 함).

**결론:** 필드 정확도 기준으로는 시연용 4B로 쓸 만한 수준에 도달했지만, 되묻기 유형 판단과 새 문장 일반화는 8B에 못 미치고 v3에서 일부 후퇴했다. 팀 최종 후보(8B)를 대체하기보다 가볍게 돌리는 시연용 보조 트랙으로 보는 것이 맞다(해석).

## 5. 다음 할 일 (승인 대기)

1. 구조 일치율 보조 지표를 추가해 v2·v3를 다시 채점한다(학습 불필요). 평가 원본은 8B와 공용이므로 고치지 않는다.
2. 학습 데이터에서 충돌 표현 실제 건수, 거절 문구 조사 오류, `known` 키를 점검한다.
3. fixed-4 작성: 충돌 정리, 대조쌍(지표 하나 vs 여러 개), 부정형·흑자/적자·시가총액 보강. 평가 문항·개념어는 쓰지 않는다.
4. v4 학습(약 2시간) 후 평가. 목표: 값 되묻기 17/18 이상, 지표 모호 5/9 이상, 필드 90% 유지, 완전 일치 70% 이상. 사용자가 시작하라고 하기 전에는 학습하지 않는다.
5. 필요하면 지표 모호 비중 조절 실험(1,176건 → 약 750건 사이).
6. v3 병합 모델·GGUF를 가져와 어댑터와 같은 결과인지 확인하고, `LLM_PROVIDER=local`로 백엔드 연동을 시험한다. haechan 비교를 v3 기준으로 다시 요청한다.

## 6. 아직 확인하지 않은 것

- 학습 데이터의 충돌 표현 실제 건수, 거절 문구 조사 오류, `known` 키 유무
- F·G 문항의 정확한 차이 필드
- 병합 모델·GGUF의 품질(어댑터와 동일 여부)
- 백엔드와 Q4B GGUF의 실제 연동 호출
- v3의 새 문장(시험 3세트) 성능
