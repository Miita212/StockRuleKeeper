## 2. 가장 큰 문제: A (11건)

v2는 되묻기(값 없음) 17/18이었는데 v3는 12/18이다. 지표 모호 되묻기를 430 → 1,176건으로 늘리면서 값 되묻기(1,335건)와 경계가 흐려졌다. 증상은 양방향이다.

- "영업이익이 높은 회사", "빌린 돈에 많이 기대는 회사"처럼 **지표가 하나로 정해지는데** 후보를 묻는다.
- "빚 걱정 없는 회사", "이익이 늘어나는 회사", "규모가 큰 회사"처럼 **지표가 여럿인데** 값을 묻는다.

즉 모델은 "이 표현이 몇 개 지표로 갈리는가"를 구분하지 못하고 있다. 표현 → 지표 개수 대응이 데이터에서 일관되지 않을 가능성이 크다. 이전 `v3_conflict_audit.csv`에서 같은 표현이 양쪽으로 학습된 것이 6개 나왔는데 자동으로 고치지 않았다. 이것이 원인일 수 있으나 **아직 확인하지 않았다.**

### 조치
1. **충돌 표현 전수 점검(먼저 할 일).** `train_fixed3.jsonl`에서 평가 오답 문항의 핵심어(영업이익이 높은, 빌린 돈에 기대는, 빚 걱정, 이익이 늘어나는, 규모가 큰, 출렁)와 비슷한 표현이 어느 쪽 정답으로 몇 건 들어 있는지 센다. 외부 LLM 449건(그룹 G1~G18)이 "지표 하나로 정해지는 표현"까지 모호로 만들었는지 본다.
2. **외부 LLM 449건 중 지표가 하나로 정해지는 그룹 제거 또는 값 되묻기로 재라벨.** 그룹 표에서 후보가 1개로 수렴하는 그룹이 있는지 확인한다.
3. **대조쌍 추가.** 같은 틀에서 지표가 하나인 표현(값 되묻기)과 여러 개인 표현(지표 되묻기)을 짝지어 넣는다. 평가 문항·평가 개념어는 쓰지 않는다(v3 원칙 유지).
4. 모호 되묻기 비중은 v2 수준(약 750건)과 v3(1,176건) 사이로 되돌려 실험한다. 한 번에 한 변수만 바꾸려고 3번과 4번은 따로 학습한다.

## 3. 채점 문제부터 정리해야 한다 (C, F, G)

학습을 새로 하기 전에 평가 정답부터 확인해야 한다. 정답 문구 자체에 문법 오류가 있다.

- H5a-033 정답: "매출순이익률**나** 영업이익 **볼 수 있어요**" / 모델: "매출순이익률**이나** 영업이익**으로** 볼 수 있어요" (모델이 더 맞는 문장)
- H5b-033 정답: "EPS 증가율**는**…" / 모델: "EPS 증가율**은**…"
- 거절 8건 중 구조(`refusal: true`, `indicators: []`)는 6건이 맞고, 문구만 달라 0/8로 채점된다.
- H5a-036(종목 추천 거절)은 문구뿐 아니라 **내용이 틀렸다**(지표 안내 문구로 거절). H5b-035도 같은 유형인지 확인이 필요하다.
- H5c-033은 정답에 `known` 키가 있고 모델은 안 냈다. 학습 데이터에 `known`이 있었는지 확인한다.

### 조치
1. 평가 세트를 고치는 것은 팀 합의가 필요하다(8B와 공용 111문항). **Q4B 자체 기준은 따로 정해도 된다는 합의**가 있으므로, 원본은 두고 보조 지표를 추가하는 쪽을 권한다.
2. 보조 지표 `구조 일치율`: 거절은 `refusal`·`indicators` 구조와 거절 종류(20개 밖/종목 추천/매매 시점)만 보고, 되묻기는 `reason`·`indicator_id`·`candidates`·`options` 값만 본다. 문구는 제외한다.
3. 이 지표로 v2·v3를 다시 계산한다. 원인 C·F를 빼면 실제 모델 개선폭이 어느 정도인지 알 수 있다.
4. 거절 문구 템플릿의 조사 처리(나/이나, 는/은, 볼/으로 볼)를 학습 데이터 생성 코드에서 확인한다. 학습 데이터도 같은 오류를 가졌다면 모델이 올바른 문장을 내는 것은 오히려 데이터 밖에서 일반화한 것이다.

## 4. 그 밖의 모델 문제 (D, E)

- **15~18번(주가 지표) 혼동(H5c-007, 011, 012).** 52주 저점 대비(17), 고점 대비(16), 기간 수익률(15)이 헷갈린다. "~% 넘게 오른 건 제외"처럼 **부정·제외 표현이 들어가면 연산자와 번호가 같이 틀린다.** 부정형 문장(제외·빼줘·말고)을 번호별로 40~60건 보강한다.
- **H5a-009 "영업이익이 흑자인"을 거절.** "흑자 = 영업이익 > 0"(5번). 학습 데이터에 흑자·적자 표현이 부족한 것으로 보인다(미확인). 흑자·적자·플러스·마이너스 표현을 5번 지표로 20~30건 보강한다.
- **user 지표 누락(H5c-003, 022).** 시가총액이 포함된 문장에서 14번이 빠졌다. "시총/시가총액 + 금액" 단일·복수 문장을 보강한다. H5c-003은 "2000억은 되는"에서 값을 10000으로 냈다(기본값으로 회귀). "~은 되는" 같은 어미 변형에 주의한다.
- 오답 문항의 표현은 그대로 보강에 쓰면 평가가 암기로 오른다. **같은 유형의 다른 표현**으로만 만든다.

## 5. 학습 설정

- eval_loss는 v2 0.0093, v3 0.0113으로 높은데, val 데이터가 바뀌어서(270 → 337대화) 직접 비교할 수 없다. 설정 변경은 근거가 약하다.
- 에폭 3은 유지한다. eval_loss가 2.5 → 3.0에서 0.01161 → 0.01123으로 거의 안 줄어든다. 에폭을 늘리는 것은 권하지 않는다.
- 이번에는 데이터 조치 효과를 보려고 **하이퍼파라미터는 그대로** 둔다.

## 6. 실행 순서 (제안)

| 단계 | 내용 | 비용 |
|---|---|---|
| 1 | 구조 일치율 지표 추가, v2·v3 재채점 (학습 없음) | 코드 수정 + 수 분 |
| 2 | 충돌 표현 전수 점검(2절 1·2), 거절 템플릿 조사 오류 확인(3절 4), `known` 키 학습 데이터 확인 | 사람이 결과를 보고 판단 |
| 3 | 데이터 fixed-4 작성: 충돌 정리 + 대조쌍 + 부정형·흑자·시총 보강 | 코드 + 검수 |
| 4 | v4 학습(약 2시간, 원격 PC) → 평가 | GPU 2시간 + 평가 |
| 5 | 모호 비중 조절 실험(2절 4)은 4단계 결과를 본 뒤 필요하면 | 학습 1회 추가 |

1~2단계는 학습 없이 끝나므로 먼저 하고, 그 결과로 3단계 범위를 확정한다.
