# fixed-5 추가 데이터 검증 체크리스트

작성: 2026-11-09, yappang. 추가 데이터 생성은 다른 팀원이 맡고, 받은 데이터를 yappang이 검증한다.
배경과 기준: `fixed5-draft.md`(수정안), `q4b-v4-evaluation.md`(평가). 학습은 사용자가 시작하라고 하기 전에는 하지 않는다.

## 0. 받을 때 요청할 것 (생성 담당자에게)

- 형식: `train_fixed4.jsonl`과 같은 한 줄 JSON `{"messages":[system,user,assistant], ...}`. 새 파일로 주고 기존 파일은 고치지 않는다.
- 유형별 파일 또는 `kind` 필드로 구분(대조쌍 / 거절 오판 방지 / 20개 밖 변형 / 정리 수정).
- 기존 데이터를 **수정**한 경우 수정 전·후 대응표(CSV: 행 번호, 수정 전, 수정 후, 이유)를 같이 준다.
- 시험 문장(`test_set.jsonl` 234문항)과 비슷한 문장은 만들지 않는다. 시험 문장 그대로는 자동 검사에서 막힌다.

## 1. 자동 검사 (스크립트)

```
cd members/yappang
python3 -I -X utf8 data/scripts/check_new_data.py <신규.jsonl>
```
스크립트: `data/scripts/check_new_data.py`. 실패가 하나라도 있으면 종료코드 1.

| 번호 | 검사 | 기준 | 자동 |
|---|---|---|---|
| 1 | 형식 | role 순서 system→user→assistant, 응답이 JSON이거나(지표 설명은 일반 텍스트 허용) `{`로 시작하면 JSON이 깨지지 않음 | ✅ |
| 2 | 시험 문장 중복 | `test_set.jsonl` 234문항과 동일 문장 0건 | ✅ |
| 3 | 기존 중복 | `train_fixed4`·`val_fixed4`와 동일 문장 0건 | ✅ |
| 4 | 신규 내부 중복 | 같은 문장 2회 이상 없음 | ✅ |
| 5 | 되묻기 형식 | `reason`이 `AMBIGUOUS_INDICATOR` / `VALUE_MISSING` / `PERIOD_MISSING`, 값 되묻기는 `indicator_id`가 1~20 | ✅ |
| 6 | 거절 문구 조사 | "…아직 쓰지 않는 지표예요"로 시작하면 "…로/으로 볼 수 있어요."로 끝남, "~률나", "~률는" 없음 | ✅ |
| 7 | 모호 후보 | 후보 2~4개, 키는 `id`·`label`(`name` 아님), id 오름차순·중복 없음·1~20 | ✅ |
| 8 | 변환 | 지표 20개(id 1~20 각 1회), 연산자 `< <= > >=`, source는 `user`/`default` | ✅ |
| 9 | 시험 유사 문장 | 띄어쓰기·문장부호를 뺀 유사도가 0.75 이상이면 실패, 0.65 이상이면 경고(정답 유형·지표가 같으면 "정답 같음" 표시). 경고는 사람이 읽고 판단. 예: 신규 "회사 순자산보다 싸게 거래되는 주식" ↔ 시험 "순자산보다 싸게 팔리는 주식" 0.74(정답 같음) | ✅ |
| 경고 | 주제어 단위 후보 집합 | 메시지 첫 구절이 같은데 후보 집합이 2종 이상이면 경고(실패는 아님, 아래 3절에서 판단) | ✅ |

기준 확인: fixed-4 첫 300건으로 돌렸을 때 "기존 중복"만 실패로 나왔고 형식 오류는 0건이었다. 현재 기존 데이터에서도 경고로 나오는 것: "어떤 기준으로 볼까요?"(후보 3종), "싸다고 볼 수 있"(10·11 / 10·11·16 두 갈래).

## 2. 수치 검사 (사람이 보는 표)

신규 + 기존 합친 뒤의 분포를 본다. v3에서 모호 비중이 커서 값 되묻기가 후퇴한 사례가 있어서 쏠림을 확인한다.

| 번호 | 항목 | 확인 방법 | 합격 기준(제안) |
|---|---|---|---|
| 10 | 규모 | 신규 건수 | 대조쌍 약 240, 거절 오판 방지 약 40, 20개 밖 변형 약 100 (±20%) |
| 11 | 유형 비율 | 지표 모호 / 값 되묻기 / 거절 / 변환 비율 | 모호 비중이 fixed-4(약 1,237/6,942=17.8%)를 크게 넘지 않음. 값 되묻기와 비율이 뒤집히지 않음 |
| 12 | 대조쌍 균형 | 주제어마다 모호 문장과 "지표 하나로 정해지는" 문장이 쌍으로 있는지 | 쌍마다 1:1, 주제어당 10쌍 안팎 |
| 13 | 20개 밖 변형 | 개념당 표현 수 | 개념당 3~5표현, 20개 안 지표와의 대조쌍 포함 |

## 3. 사람이 읽고 확인할 것 (표본 검수)

신규 데이터에서 유형별로 무작위 표본 약 40건씩을 읽는다(재현 가능하게 시드를 기록).

| 번호 | 항목 | 질문 |
|---|---|---|
| 14 | 모호 판단 기준 | 문장이 가리키는 20개 중 지표가 둘 이상이고 사용자가 하나를 지목하지 않았나? (`fixed5-draft.md` 3.1) |
| 15 | 후보 집합 | 주제어별 표준 집합(3.2절 표)과 같은가? 다른 집합이면 이유가 있나? |
| 16 | 메시지 문구 | 첫 구절이 사용자 말의 핵심어를 인용하나? 일반 문구는 핵심어가 없을 때만인가? |
| 17 | 대조쌍의 정답 유형 | 지표 하나로 정해지는 쪽이 값 되묻기(값 없음) 또는 변환(값 있음)으로 정확히 갈렸나? |
| 18 | 20개 밖 거절 | 정말 20개에 없는 개념인가? 20개 안 지표의 별칭을 거절로 만들지 않았나? ("빚 걱정"→부채비율은 거절이 아니라 모호) |
| 19 | 거절 안내 문구 | 대안으로 든 지표 2개가 개념과 관련 있고, 조사 오류가 없나? |
| 20 | 말투 | 기존 데이터와 같은 해요체인가? 지표 이름이 20개 이름과 정확히 같은가? |
| 21 | 수정한 기존 데이터 | 대응표대로 수정됐고, 수정이 확정한 규칙을 어기지 않나? |

## 4. 합친 뒤 검사 (통합 단계)

1. 기존 fixed-4와 합친 새 train/val을 만든다(분리 규칙: val은 기존 val 유지, 신규는 train).
2. 합친 파일에 `check_new_data.py`를 한 번 더 돌린다(기준 파일을 새 val로).
3. 시험 234문항과 동일 문장 0건, train–val 동일 문장 0건을 다시 확인한다.
4. sha256, 건수, `DATA_VERSION.md`(fixed-5 변경점), 변경 기록을 갱신한다.
5. 합격 후에만 학습한다. 학습은 사용자가 시작하라고 한 뒤에 한다.

## 6. 이미 알려진 확인 사항

- "싸다" 후보를 하나로 통일해야 한다(10·11·16 vs 10·11). 표준 확정 전에는 신규 데이터에서 이 주제를 만들지 않는다.
- "매출이익률이 높은 기업"이 5·6·7(99건)에 있는 것, "주요 활동 수익성"이 5·7·8·9(9건)인 것은 오분류 가능성이 있어 해당 집합 문장 전체 검토가 필요하다.
- 기존 학습 데이터의 거절 문구 조사 오류는 0건이다(317건 확인). 시험 정답 8건은 이미 고쳤다.
