**v2에서 떨어졌는지 확인하라고 한 유형 (지시서 9절):** "되묻기(값 없음)" 17/18 → 12/18, "단일" 14/16 → 12/16. **둘 다 v2보다 낮아졌다.**
- 값 없음 5건(H5a-023, 025, 026, H5b-023, 027)은 정답이 `VALUE_MISSING`(지표 확정, 값을 묻기)인데 모델이 `AMBIGUOUS_INDICATOR`(어떤 지표로 볼까요)로 되물었다.
- 단일 새 오답 5건 중 H5a-002, 003, H5b-007은 지표·값이 맞고 안내 문구만 달랐다(채점은 틀림). H5a-020은 오타 문항으로 같은 유형. H5c-003은 값 오류(정답 2000, 모델 10000).

형태 불일치 (정답→모델): VALUE_MISSING→AMBIGUOUS_INDICATOR 6, AMBIGUOUS_INDICATOR→VALUE_MISSING 4, 지표 입력→AMBIGUOUS_INDICATOR 1, 지표 입력→VALUE_MISSING 1.

채점 관련 (고치지 않고 건수만):
- "문구·키 차이뿐"인 오답(안내 문구와 후보 키를 정규화하면 정답과 같은 것): v2 9건 → v3 **9건**. 거절(20개 밖) 8건 중 6건이 여기 포함됨(구조는 맞고 문구가 다름).
- v3가 candidates에 `name` 키를 쓴 문항: **0건** (`label`로 통일됨).
- 거절 문구의 내용 오류 예(고치지 않고 기록): H5b-031 "PEG"에 "PSR는 아직 쓰지 않는 지표예요", H5a-036(종목 추천 거절)에 지표 안내 문구.

**해석 (측정이 아닌 추정):**
- 필드 정확도는 목표 90%에 도달했고, 완전 일치율은 +2.7%p로 개선 폭이 작다.
- 지표 모호 되묻기를 크게 늘린 것(430→1,176건)이 "되묻기(값 없음)"과 "단일" 일부를 떨어뜨린 것으로 보인다. 같은 표현이 지표·값 되묻기로 갈릴 때 모델이 지표 되묻기 쪽으로 기운다.
- 지표 모호 되묻기는 0/9 → 2/9로 목표에 한참 못 미친다(나머지 7건 중 4건은 값 되묻기로, 3건은 문구 불일치). 다음 개선 과제로 남는다.
- 거절(20개 밖)은 8건 모두 엄격 채점에서 틀렸다. v2는 되묻기·지표 값으로 답한 경우가 많았는데 v3는 거절 형태로 답하는 쪽이 늘었으나(예: H5c-037), 문구가 정답과 달라 점수에 반영되지 않았다.

## 5. 이상 징후
- 학습·평가 중 오류, OOM, nan, 재시작 없음. 경고는 HF Hub 비인증 요청 안내 1건뿐(`HF_TOKEN` 미설정).
- 체크포인트는 스크립트 설정상 3개만 남음(642, 856은 삭제됨). 별도 조치 아님.
- 감시용 Monitor(Claude Code 도구)가 30분마다 만료되어 여러 번 다시 걸었다. 학습에는 영향 없음.
- 지시서 문서 안에서 언급되는 `docs/q4b-handoff.md`, `docs/q4b-plan.md`는 이 폴더에 없었다(작업에는 영향 없음).

## 6. 지시서와 다르게 한 것 / 하지 못한 것
**지시서 "하지 않는 일"이지만 사용자가 직접 요청해 한 것:**
- 병합: `scripts/merge_adapter.py --nf4 --adapter outputs/q4b-v3 --out outputs/q4b-v3-merged-nf4` (복원한 Linear4bit 252개, 8.0GB, 로그 `merge_q4b_v3.log`). 병합 모델 자체의 품질 평가는 하지 않았다.
- GGUF 변환: `outputs/stockrule-q4b-v3.Q8_0.gguf` (4,280,404,928바이트, 로그 `gguf_convert_q4b_v3.log`). GGUF를 실제로 불러 추론해 보지 않았다(llama.cpp 실행 파일·Ollama 없음).
  - 변환 도구: llama.cpp 저장소(깊이 1 복제, 커밋 `9982004`)를 `q4b-v3-remote/tools/llama.cpp/`에 복제. 변환 스크립트에 네트워크·하위 프로세스·삭제 호출이 없는 것을 grep으로 확인했다(전수 코드 검토는 아님).
  - `convert_hf_to_gguf.py`가 `sentencepiece` 모듈을 요구해, `pip install --target tools/pydeps --no-deps sentencepiece==0.2.0`로 **학습용 venv 밖**에 설치하고 PYTHONPATH로만 썼다. 학습용 venv의 패키지 버전은 바뀌지 않았다.

**하지 못했거나 건너뛴 것:**
- Ollama 등록, GGUF·병합 모델의 평가 재실행은 하지 않았다.
- `data_used.json`의 sha256 일치 외에 학습 데이터 내용 자체의 검증은 하지 않았다(지시서 범위 밖).
- 데이터·스크립트·평가 파일·채점 코드는 수정하지 않았다.
