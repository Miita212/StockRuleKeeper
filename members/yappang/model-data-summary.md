### 1.2 하드웨어 조건 (사용자 제공)
- 학습: RTX 4090 (24GB) / 추론: 노트북 RTX 4060 (8GB [일반, 실제 확인 필요])
- 모델 크기 상한은 **추론 장비(8GB)** 가 정한다. 3~8B급을 4비트 양자화해 구동, 14B 이상 제외.
- 흐름: 4090에서 QLoRA 학습 → 어댑터 병합 → 4비트(GGUF 등) 변환 → 노트북 추론. 평가는 **양자화 전후 두 번**.
- 시연 구성: 노트북이 모델 서버 + 백엔드. 상시 서비스에는 부적합(앱인토스 배포 요건은 확인 필요).
- 외부 API는 비교 기준선·예비 경로.

### 1.3 모델 후보 비교 (한국어 중시) — 3.1절
| 항목 | **Qwen3-8B** | EXAONE 3.5 7.8B | Gemma 3 4B |
|---|---|---|---|
| 4비트 VRAM [일반] | 약 5~6GB | 약 5GB | 약 3GB |
| 한국어 | 양호 | **한국어 특화** | 양호, 크기 한계 |
| JSON·지시 따르기 [일반] | 강함 | 보통~양호 | 보통 |
| 미세조정 사례 [일반] | 매우 많음 | 적음 | 많음 |
| 라이선스 | Apache 계열로 알고 있음 (**확인 필요**) | 연구·비상업 중심 (**확인 필요**) | Gemma 약관 |
| 속도 [일반] | 중간 | 중간 | 가장 빠름 |

**1순위: Qwen3-8B** — 이 앱의 일은 "한국어 → 정해진 JSON"이라 한국어 문체보다 이해력과 구조화 출력 안정성이 먼저. 사고(thinking) 모드는 끄고 사용. **2순위** EXAONE 3.5 7.8B(한국어 품질 유리, 라이선스 위험), **3순위** Gemma 3 4B(가볍고 빠름, 대안).
- 웹 검색으로 확인한 것: EXAONE 3.5 7.8B KMMLU 44.58, 공개 한국어 모델 목록 정도. **세 모델의 직접 비교나 Qwen3 한국어 금융 점수는 확인 못 함.** 순위는 아래 평가로 확정한다.

### 1.4 파이프라인 — 4장, 11.3절
```
사용자 입력 → [모델] 지표 세트·설명 생성(JSON Schema 강제)
  → [코드] 검증 (20개 화이트리스트 / 값 범위 / operator·단위 일치 / 잠긴 지표 불변)
  → 모호하면 [모델] 되묻기+선택지 → 반복 → 승인
```
M1 출력 핵심 필드: `needs_clarification`, `anchors`, `indicators[{id, operator, value, unit, source(user|default|inferred), locked}]`, `explain_bubble`, `explain_card`. 기본값은 마스터 표에서 가져오고 모델이 만들지 않는다. 지표 목록은 6개→20개로 바뀐 이력이 있어 **시스템 프롬프트에 지표표를 항상 넣고 학습**한다.

### 1.5 평가 — 5장
- 지표: 지표 선택·값 정확도, JSON 유효율, 되묻기 판별, 응답 시간(4060 실측), **잠금 준수**, **리포트 숫자 일치**, 해요체 자연스러움(팀원 3명 이상 평가).
- 먼저 **용어 진단 테스트**(지표 정의·좋은 방향·구어체 매핑·단위)로 후보 3개의 금융 용어 이해를 점검 → 약한 지표는 보강. 한국어 금융 용어가 약하면 순위가 바뀔 수 있다.
- 목표치는 기준선 측정 후 팀과 정한다.

### 1.6 위험 — 6장
종목 추천·예측처럼 들리는 답변(톤 규칙으로 방지), 20개 밖 지표 요구(검증 코드 거절), 환각(숫자·용어는 사전/코드 우선), 지연, 양자화 품질 저하, 노트북 열·전원 상태.

## Part 2. 데이터

### 2.1 핵심 원칙 — 10.1절
- 파인튜닝 목적은 "주식 지식 주입"이 아니라 **초보자 말 → 지표 JSON 변환의 안정화**. 사실(정의·기준값·업종 평균)은 사전에서 주입.
- "업종 평균 100% 안팎"은 여러 화면에 고정 문구로 나오지만 **출처가 없다** → 사전에 근거와 함께 기록해야 한다.

### 2.2 주식 용어 위험과 대응 — 10.2, 11.5절
| 위험 | 대응 |
|---|---|
| 구어체 ↔ 공식 용어 (빚 → 부채비율/차입금의존도/이자보상) | 구어체 동의어 사전 + 되묻기 |
| 한 말이 여러 지표 ("비싸다": PER/PBR/52주 고점) | 포괄 표현 → 지표 묶음 규칙을 팀이 정함 |
| **같은 지표의 이름이 화면마다 다름** (매출 성장률/매출액 증가율, 배당수익률/12개월 배당수익률, PER/주가수익비율) | 별칭표 + **모델은 `id`만 출력, 이름은 코드가 붙임** |
| 연산자 4종 이하/이상/이내/초과 | 마스터에 지표별 부등호 명시. `이내`는 판정서 예시로 "변화폭이 한도 이하"로 읽힘 [추론]: 52주 고점 대비 −20% 이내에 −8.1% 충족, 저점 대비 50% 이내에 +38% 충족 → 팀 확인 |
| "흑자" = 영업이익 0억 초과 [PDF 02·04·11] | 사용자 "적자 기업은 제외"를 `영업이익 > 0`으로 매핑하는 예시 포함 |
| 방향 혼동 ("빚 적은" ↔ 부채비율 이하) | 극성 반전 예시, 검증 코드가 방향 차단 |
| 단위 (%, 배, 년, 억/조원) | 마스터에 `unit`·허용 범위, 단위 변환 예시 |
| 8B급의 용어 지식 부족 | 용어 진단 후 정의 질의응답 추가 + 프롬프트 주입 |

### 2.3 사람이 직접 만들어야 하는 것 (필수) — 10.3절
| # | 산출물 | 내용 | 규모 [제안] |
|---|---|---|---|
| H1 | 지표 마스터 JSON | id, 정식명·UI명·약어·카드 요약명, 영역, operator, unit, 범위, 기본값, 정의, 상대 표현 증감폭 | 20행 |
| H2 | 구어체 동의어 사전 | 지표별 초보자 표현, 포괄 표현 → 지표 묶음 규칙 | 지표당 10~20개 |
| H3 | 되묻기 정책 | 되묻는 조건, 선택지 3개(엄격·보통·느슨) 규칙과 근거 | 규칙 1장 + 선택지 60개 |
| H4 | 시드 학습 예시(gold) | 단일·복수 지표, 모호, 수정, 거절, 오타·줄임말·반말 | 150~300 |
| H5 | 평가 세트(gold, 분리) | 학습에 쓰지 않음. 용어 진단·잠금·숫자 일치 포함 | 100~150 |
| H6 | 말투·안전 가이드 | 해요체, 한글+약어 병기, 추천·예측·보장 금지, 거절 문구 | 1~2장 |
| H7 | 합성 데이터 검수 | 무작위 10~20% 사람 확인 | 건수 비례 |
| H8 | 리포트 톤 가이드 | 원인 단정·예측·매수 권유 금지, 표본 한계 언급 | 1장 |

시작 씨앗: 기획보고서 사례(지혜/민수)와 01 추천 문구 5개(빚 많은 회사 / 배당 꾸준 / 너무 비싼 주식 / 적자 기업 제외 / 성장하는 회사). 5개의 지표 매핑이 맞는지 팀 확인 필요.

### 2.4 내려받아 쓰는 것 (참고·보강) — 10.4절
공개 자료는 용어·정의·평가 참고용이며 **JSON 형식이 달라 그대로 학습 데이터가 되지 않는다.** 사용 전 라이선스·이용조건을 직접 확인.
| 자료 | 용도 | 확인 상태 |
|---|---|---|
| 금융위원회 금융용어사전 (공공데이터포털 파일·API) | 정의 원문 → H1·H2 | [검색] 존재 확인. 일부 용어만, API 응답에 HTML 태그(정제 필요) |
| 한국은행 경제금융용어 700선 등 | 정의 대조 | 이번 검색에서 못 찾음 → 직접 확인 |
| FINKRX 오픈 금융 데이터(8만 건), KRX-Bench, KFinEval-Pilot | 용어 진단·평가 참고 | 논문으로 존재 확인. 저장 위치·라이선스는 직접 확인 |
| 공개 한국어 지시 데이터 | 일반 능력 유지용 소량 혼합 | 목록·라이선스 선택 시 확인 |
| Qwen3-8B 모델·토크나이저·채팅 템플릿 | 학습 기반 | HF 모델 카드에서 라이선스 확인 |
- 일반 금융 질의응답은 전체의 **10~20% 이하**로 섞고 효과를 평가로 확인 [제안].

### 2.5 자동 생성(합성) — 10.5, 11.4절
| # | 유형 | 목표 [제안] |
|---|---|---|
| S1 | 원칙 해석 변형 (존댓말·반말·줄임말·오타·영어 약어) | 1,500~3,000 |
| S2 | 복수 지표·포괄 표현 | 300~500 |
| S3 | 되묻기 대화(여러 턴) | 300~500 |
| S4 | 수정 diff (**잠긴 지표 불변 사례 포함**) | 500~1,000 |
| S5 | 거절·무관 입력 | 200~400 |
| S6 | 용어 질의응답 (진단에서 약한 지표 위주) | 지표당 3~5 |
| S7 | 설명 말풍선 (M4) | 200~400 |
| S8 | **리포트 서술** (입력 JSON → 제목·변경 요약·종목 변화) | 300~500 |

- 생성은 외부 LLM 또는 4090에서 돌릴 수 있는 큰 로컬 모델. **외부 서비스 생성물로 다른 모델을 학습해도 되는지 약관 먼저 확인.**
- 자동 검증(전부 통과분만 사용): JSON 스키마, 지표 id가 20개 안, 값 범위, operator·단위 일치, 잠긴 지표 불변, 중복 제거, 금지 표현 필터, **S8은 문장 속 숫자·종목명이 입력과 정확히 일치**.
- **평가 세트와 겹치는 문장 제거.** 같은 시드의 변형은 학습 또는 평가 한쪽에만.
- 리포트의 주의 문구·"스스로 판단해 보세요" 질문은 템플릿으로 두고 모델은 3블록만 생성.

### 2.6 학습 형식·분할·보관 — 10.7절
- 형식: Qwen3 채팅 템플릿 `system`(지표표+규칙) / `user` / `assistant`(JSON). 사고 모드 끔.
- 분할: 학습/검증/평가 약 8:1:1, 평가는 H5 별도.
- 규모 감각: 합쳐서 3,000~5,000개 [일반, 실측 필요].
- **데이터·모델은 대용량이라 커밋하지 않는다**(팀 규칙). 마스터 JSON과 가이드 문서만 커밋 대상. 지표 마스터 형식은 `docs/interface.md`에서 다른 담당자와 맞춘다.
- 학습 문장에 실제 이름·계좌·실투자 정보 사용 금지.

## Part 3. 작업 순서 (10일 MVP) [제안]
1. H1 지표 마스터 + 부등호(`이내` 등) 통일 → 팀 확인
2. 노트북(4060)에서 후보 모델 2~3개 **속도·VRAM 실측** + 용어 진단 → 순위 확정
3. H2 동의어 사전, H3 되묻기 정책, H6·H8 가이드
4. H4 시드 + H5 평가 세트 (작성자 분리)
5. S1~S8 합성 + 자동 검증 + H7 사람 검수
6. QLoRA 학습 → 4비트 변환 → 양자화 전후 평가
7. 약한 지표 보강 후 재학습, 검증 코드·`api/index.ts` 연결

## Part 4. 팀에 확인할 것
1. 자물쇠(잠금) 규칙: 어떤 지표가 기본 잠금인지, 잠금 해제는 누가 하는지 [추론 단계]
2. 부등호 규칙(`이내`, `초과`)을 지표별로 확정
3. 지표 마스터를 작성·검수할 금융 지식이 있는 팀원, 기본값 표 검토 담당
4. "업종 평균 100% 안팎" 등 기준 수치의 출처
5. 포괄 표현("안전한 회사")의 지표 묶음 규칙, 01 추천 문구 5개의 지표 매핑
6. "성장성도 보고 싶어"(08 칩)가 20개 전체를 쓰는 원칙에서 무엇을 바꾸는지
7. 리포트(13) 구현 범위와 산출 방식 (화면은 PDF에 설계됨, 수치는 "예시 데이터")
8. 노트북 RAM·OS와 VRAM(8GB) 실제 확인, 시연 때 노트북 모델 서버 허용 여부
9. 공공 용어사전 이용조건, 합성 데이터 생성 서비스 약관, 모델 라이선스(Qwen3 등)
10. 앱인토스 배포 요건 중 서버 호출·외부 API 제약
