## 3. 진단: 학습한 문장을 그대로 넣어 보기 (v2)

`diag_train_samples.py`로 v2 학습 데이터의 문장을 유형별 20개씩 v2 모델에 넣었다.

- 추출 정답 20개 → 거절 19, 되묻기 1 (추출 0)
- 되묻기 정답 20개 → 전부 거절
- 거절 정답 20개 → 전부 거절

→ **학습한 문장조차 틀린다.** 평가셋과 학습 데이터의 분포 차이가 아니라 학습 과정 쪽 문제.

추가로 확인한 것
- 거절 메시지 안에 질문과 맞는 지표 이름이 나온다(예: "본업 이익이 늘어나는 회사" → "매출순이익률이나 영업이익으로 볼 수 있어요"). 질문 이해는 되고, **답 유형을 고르는 순간에만** 쏠린다.
- 학습·평가 프롬프트는 같은 함수(`apply_chat_template`, `enable_thinking=False`)로 만들며 끝이 `<think>\n\n</think>\n\n`로 같다. `train_qlora.py`의 라벨 마스킹(질문은 가리고 답만 학습)도 정상.
- 첫 토큰은 모든 유형에서 `{"`(확률 92~100%)라 구분이 안 된다. 유형은 **두 번째 토큰**(`indicators` / `needs_clarification` / `refusal`)에서 갈린다.

다음 할 일

2. 확인되면 `train_qlora.py`에서 결정 토큰 손실에 가중치를 주고 재학습.
3. 그래도 안 되면 few-shot 방식으로 돌리는 것을 팀에 제안.

**정답 유형별 응답 (3에폭):** 추출 67건 → 추출 66·거절 1 / 되묻기 30건 → 전부 되묻기 / 거절 14건 → 거절 10·되묻기 4

**최종 후보: v3 3에폭 (`qwen3-8b-v3-3ep-haechan`)**
- 이 모델의 주된 일인 추출에서 가장 좋다: 사용자가 말한 값 반영 75.0%(2에폭 +7.5%p), 추출 전체 일치 68.7%(+7.5%p), 기본값을 잘못 바꾼 지표 13개로 가장 적음.
- 거절은 2에폭보다 1건 적게 맞혔다(11/14 → 10/14). 평가 건수가 14건이라 오차 범위에 가깝다.
- 남은 약점: 거절해야 할 질문 4건을 되묻기로 답함. 앱에서 거절 판단을 코드로 한 번 더 확인하면 보완 가능.

**어댑터 가중치:** 저장소에는 없음(크기·팀 규칙). haechan이 따로 공유. 받은 어댑터는 `chat_adapter.py --adapter <폴더>`로 바로 시험해 볼 수 있다(원본 Qwen/Qwen3-8B 4bit + 어댑터, GPU 약 7GB).
