## 3. 진단: 학습한 문장을 그대로 넣어 보기 (v2)

`diag_train_samples.py`로 v2 학습 데이터의 문장을 유형별 20개씩 v2 모델에 넣었다.

- 추출 정답 20개 → 거절 19, 되묻기 1 (추출 0)
- 되묻기 정답 20개 → 전부 거절
- 거절 정답 20개 → 전부 거절

→ **학습한 문장조차 틀린다.** 평가셋과 학습 데이터의 분포 차이가 아니라 학습 과정 쪽 문제.

추가로 확인한 것
- 거절 메시지 안에 질문과 맞는 지표 이름이 나온다(예: "본업 이익이 늘어나는 회사" → "매출순이익률이나 영업이익으로 볼 수 있어요"). 질문 이해는 되고, **답 유형을 고르는 순간에만** 쏠린다.
- 학습·평가 프롬프트는 같은 함수(`apply_chat_template`, `enable_thinking=False`)로 만들며 끝이 `<think>\n\n</think>\n\n`로 같다. `train_qlora.py`의 라벨 마스킹(질문은 가리고 답만 학습)도 정상.
- 첫 토큰은 모든 유형에서 `{"`(확률 92~100%)라 구분이 안 된다. 유형은 **두 번째 토큰**(`indicators` / `needs_clarification` / `refusal`)에서 갈린다.

다음 할 일

2. 확인되면 `train_qlora.py`에서 결정 토큰 손실에 가중치를 주고 재학습.
3. 그래도 안 되면 few-shot 방식으로 돌리는 것을 팀에 제안.

### 왜 데이터를 추가했나
공식 평가셋 111건만 보면 v3 3에폭이 좋아 보이지만, **표현을 조금만 바꾸면 약점이 크게 드러난다.** v3 3에폭에 보강 문장 233건(아래)을 넣어 보니:

| | 공식 평가셋 111건 | 보강 문장 233건 |
|---|---|---|
| 거절 정확도 | 71.4% | **18.4%** (76건 중 14) |
| 추출 전체 일치 | 68.7% | **43.3%** (157건 중 68) |
| 사용자 지정 지표 | 75.0% | **54.7%** |
| 불필요한 되묻기·거절 | 1.5% | **12.1%** |

v3가 틀리는 유형:
1. **20개 밖 개념을 이름 없이 풀어 말하면 거절하지 못함.** "외국인이 많이 들고 있는 회사" → 부채비율 되묻기, "직원이 천 명 넘는 회사" → 거래대금 추출. 기존 거절 데이터는 대부분 "ROE 높은 회사"처럼 지표 이름을 직접 말한다.
2. **"~찾아줘"로 끝나면 추출할 문장도 거절함.** 학습 데이터에서 "찾아줘"로 끝나는 문장은 거절 25·되묻기 2·**추출 0**이라, 모델이 "찾아줘"를 거절 신호로 배웠다. ("~만 보여줘"도 거절 72·추출 21로 치우침.) 공식 평가셋에는 "찾아줘"로 끝나는 추출 문장이 없어서 드러나지 않았다.
3. **헷갈리는 지표 짝**: 저점 대비(17)↔변동성(18)·거래량(20), 고점 대비(16)↔저점 대비(17), 부채비율(1)·차입금의존도(2)·자본잠식률(4), 매출(8)↔영업이익(9) 증가율, 연속 배당(13)↔연속 흑자(6).
4. **지표 2개 중 하나를 빠뜨림**, **"넘게·넘는"(>)을 ≥로**, "고점 대비 N% 넘게 떨어진"(< -N)을 반대 방향으로.

### 해석
- **보강 목표는 이뤘다.** "~찾아줘" 추출 문장을 거절하던 문제(A)와 지표 짝 혼동(D)이 줄었고, 보강에도 없는 새 20개 밖 개념의 거절(B)이 늘었다. 평가 개념을 일부러 빼고 만든 보강이라 공식 거절 71.4 → 85.7%도 외운 결과가 아니다.
- **거절 과다는 거의 없다.** C 4/4 유지, 공식 불필요한 되묻기·거절 2건(v3 1건), 시험은 11.1% → 5.6%.
- **남은 약점 (v4 3에폭)**
  - E 그룹 틀린 4건 중 3건이 "넘는"(>)을 "이상"(≥)으로 읽은 부등호 오답(나머지 1건은 영업이익을 빠뜨리고 거래대금을 넣음). "PBR이 1배가 안 되는"(<)도 ≤로.
  - "52주 신고가에서 10% 이내"를 저점 대비(17)로 읽음(모든 버전 공통). 정답 16 ≥ -10.
  - "영업이익 500억 넘는 회사 찾아줘", "배당수익률이 5% 넘는 주식 좀 찾아줘"를 "쓰지 않는 지표"라며 거절. 20개 안의 지표인데 거절한 것이라 앱에서 걸러야 할 오답.
  - "배당 두둑하게 주는 회사 찾아줘"에 거절·되묻기가 섞인 답, "대표이사가 최근에 바뀐 회사는 빼줘"에 다른 형식(changes) 답.
- **되묻기 사유가 80 → 70%로 떨어졌다.** 틀린 10건 중 7건은 v3도 틀린 문장("빚 걱정 없는 회사", "규모가 큰 회사", "잘 버는 회사" 등)이고 대부분 정답 AMBIGUOUS_INDICATOR를 지표 하나의 VALUE_MISSING으로 답했다. data_v4에서 다시 붙인 되묻기 라벨 37행의 기준이 공식 평가셋 정답과 다를 수 있어 확인이 필요하다. 새로 틀린 3건: "남는 장사하는 회사가 좋아", "자산가치 대비 저렴한 회사", "가성비 좋은 주식 찾아줘"(거절함).
- 1에폭은 아직 덜 배운 상태(기본값을 38개 바꿈). 2에폭은 되묻기가 조금 낫고 시험에서 불필요한 거절 0건이지만 추출·거절·총점은 3에폭이 앞선다.

2. **부등호 라벨 35행 바로잡기** (이상→>=, 이하→<=, 미만→<, 넘는→>, "0% 이하는 제외"→> 0 등, `data_v6/EDIT_LOG_v6.csv`) + '규모' 값 묻기 4행을 공식 평가셋 기준(고르기 14·19)으로 맞춤.
3. **보강 247행** (`data_aug/gen_aug_v6.py`): 부등호·끝말 추출 198행(영업이익·배당수익률·순이익률·PBR 등 20개 안 지표 + 찾아줘/골라줘, 16번 "신고가/최고점에서 N% 이내" 표현, 두 지표 부등호), 되묻기 49행(고르기·값 묻기·기간 묻기). 공식 평가·시험과 비슷한 문장은 제외. V-1 5,922행 전부 통과. 되살린 4행(방향 모순)은 v4에서 이미 data_v5에 들어 있다.
4. **학습** `run_v5.sh`: data_v6 (train 5,603 / val 319, 학습 샘플 6,028, 에폭당 377스텝), 설정은 v3·v4와 같음(group_by_length 끔), 3에폭 1,131스텝, 6시간 9분. val loss 0.0168(377) → 0.0079(754) → **0.0067**(1131), 매번 하락.
5. **추가 시험** `test_haechan/test_haechan_v5.jsonl` 31건(H 부등호 10 · I 16·17 구분 5 · J 20개 안 지표 끝말 6 · K 되묻기 기준 10). 학습 보강에서 이 문장과 비슷한 것은 뺐다. 학습 금지.

### 해석
- **추출은 확실히 좋아졌다.** 공식 추출 전체 일치 82.1 → 97.0, 시험 58건 45 → 52, 이번에 새로 만든 문장(추가 시험)에서도 66.7 → 90.5. 학습에 쓰지 않은 문장에서도 오른 것이라 외운 결과가 아니다. 약점이던 '넘는' 부등호(F·H 그룹), "찾아줘"로 끝나는 20개 안 지표 문장 거절(J 6/6)이 해결됐다.
- **되묻기 사유·대상은 v4에서 떨어졌던 것을 v3 이상으로 회복**했다(86.7 / 83.3, v3 80 / 80). 시험 G 그룹 8/8.
- **거절 92.9%**(v3 71.4, v4 85.7). 공식 거절 14건 중 틀린 것은 1건("배당 성장률 높은 회사"를 거절하지 않고 되묻기).
- **주의**: '가성비' 개념은 공식 평가셋에도 있어, 공식 점수 중 되묻기 상승 일부는 개념 보강 효과다. 그래서 다른 표현("가격 대비 효율")의 추가 시험 K를 따로 두었는데, 이 그룹은 오히려 7 → 6으로 제자리다. **되묻기 기준(K)은 일반화가 약하다.**
- 2에폭과 3에폭은 추가 시험에서 26 대 25로 사실상 같다(1건 차이). 공식·시험 58건·추출 모두 3에폭이 앞선다.

- 공식 틀린 8건: "잘 버는 회사만"·"이익이 늘어나는 회사가 좋아"(고르기 기준), "남는 장사하는 회사가 좋아"(7번 대신 다른 지표), "롤러코스터"(고르기 16·18), "자산가치 대비 저렴한"(값 묻기 11 대신 고르기), "빚이 자기 돈의 두 배를 넘으면 안 돼요"·"PBR 1배 미만이면서 배당수익률 3% 이상"(추출 값 오류), "배당 성장률 높은 회사"(거절 대신 되묻기).
