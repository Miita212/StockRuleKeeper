# 모델 학습 결과 보고서 (v1 ~ v7, 4B 포함)

작성 2026-11-09 · 정해찬(haechan) · LLM 담당
대상: 사용자의 투자 원칙 문장을 JSON(추출 / 되묻기 / 거절)으로 바꾸는 모델

---

## 1. 한눈에 보기

- **최종 후보는 8B v5 3에폭**입니다. 공식 평가 111건에서 추출 전체 일치 97.0%, 거절 92.9%, 되묻기 사유 86.7%입니다.
- v1·v2는 학습 코드의 설정 하나(`group_by_length`) 때문에 실패했고, v3부터 정상 학습됩니다.
- v6은 모델이 아니라 **데이터 이름**입니다. v5 모델이 data_v6으로 학습됐습니다. (아래 3절)
- v7은 새 문장에서 v5보다 낮아서 채택하지 않았습니다.
- 4B(Qwen3-4B)는 새 데이터(fixed-4)로 다시 학습해 추출이 59.7%에서 91.0%로 올랐지만, **20개 밖 개념 거절이 거의 되지 않습니다.** 지금 상태로는 서비스에 쓰기 어렵습니다.
- 공식 111건은 개발 중 반복해서 쓴 평가라 점수가 낙관적입니다. 처음 보는 문장에서는 80~90% 정도로 봐야 합니다.

## 2. 평가 방법

| 평가 세트 | 문항 | 학습에 사용 | 용도 |
|---|---|---|---|
| 공식 111 | 추출 67 · 되묻기 30 · 거절 14 | 안 함 | 모든 버전 공통 비교 |
| 시험 58 | 58 | 안 함 | v4 준비 때 만든 약점 점검 |
| 추가 시험 31 | 31 | 안 함 | v5 준비 때 만듦 |
| 시험 v7 34 | 34 | 안 함 | v7 준비 때 만듦 |

- 채점은 `eval_model.py`(8B) 기준으로 같은 방식입니다. 4B 새 결과는 `eval_q4b.py`로 같은 234문항 세트를 채점했습니다.
- 공식 111건은 여러 버전을 고치면서 계속 봤습니다. 그래서 이 점수가 새 문장에서의 성능을 그대로 보여 주지는 않습니다.

## 4. 버전별 과정

### v1 · v2 — 실패 (한 유형으로만 답함)
- v1: 병준 님 병합본(train 2,092 / val 109대화)으로 3에폭, 2시간 35분. v2: 데이터를 조정해 1에폭, 46분.
- 결과: v1은 추출 67건을 모두 되묻기·거절로 답했고(추출 0%), v2는 거의 전부 거절로 답했습니다.
- v1의 되묻기 96.7%, v2의 거절 100%는 잘 배운 게 아니라 한 유형으로만 답해서 그 유형만 맞은 것입니다.
- **원인(확정):** 내 학습 코드에만 있던 `group_by_length=True`. 우리 데이터는 답 유형마다 길이가 달라서, 이 옵션을 켜면 배치마다 한 유형만 몰립니다. 병준 님 코드는 같은 데이터로 정상이어서, 두 코드를 비교해 찾았습니다.
- 데이터 비율이 원인이라는 처음 가설은 틀렸습니다.

### v3 — 원인 해결 (3에폭)
- `group_by_length`를 끄고 warmup·weight decay를 병준 님 코드와 맞췄습니다.
- 데이터: 병합본 train 5,202 / val 275대화(학습 샘플 5,627, 에폭당 352스텝).
- 결과: 추출 전체 일치 68.7, 사용자 지정 지표 75.0. 모든 지표에서 병준 님 v1 이상.
- 약점: 거절이 71.4%로 낮고, "~찾아줘"로 끝나는 추출 문장을 거절했습니다. 학습 데이터에서 "찾아줘"로 끝나는 문장이 거절 25·추출 0이었기 때문입니다.

### v4 — 거절·지표 혼동 보강 (data_v5)
- 보강 233행 추가(풀어 말한 20개 밖 개념 거절, 지표 혼동 추출). 평가에 나오는 개념은 일부러 뺐습니다.
- 별도 시험 58건을 새로 만들었습니다(학습 금지).
- 결과: 추출 전체 일치 82.1, 거절 85.7. 대신 되묻기 사유가 80에서 70으로 떨어졌습니다.

### v5 — 남은 약점 보강 (data_v6) ← 최종 후보
- 약점 5가지를 하나씩 보강: 부등호("넘는/안 되는"), 16번 "고점에서 N% 이내", "찾아줘" 끝말, 되묻기 기준, 잘못 지운 4행 복구. 보강 247행 추가.
- 학습: 6,028샘플, 1,131스텝, 6시간 9분, val loss 0.0168 → 0.0067.
- 결과: 추출 전체 일치 97.0, 사용자 지정 97.5, 거절 92.9, 되묻기 사유 86.7. 시험 58은 52/58.
- 남은 약점: 넓은 말의 고르기/값 묻기 경계("잘 버는", "가격 대비 효율"), 20개 밖 개념 일부, 두 지표 중 하나 빠뜨림.

### v7 — 거절 중심 보강 (data_v7), 채택하지 않음
- v6 데이터에 20개 밖 개념 거절·표현 300행을 더해 6,298행, 1,182스텝.
- 공식 111에서는 추출이 v5와 같고(97.0) 거절이 1건 낮았습니다(85.7).
- **새 문장에서는 오히려 낮았습니다.** 시험 v7 34에서 추출 81.2(v5) → 62.5(v7).
- 20개 밖 개념 거절은 10/10으로 좋아졌지만, 지표를 잘못 고르는 일이 늘었습니다.
- 거절을 늘리면 추출이 깎이는 것으로 보이며, 정확한 원인은 확인하지 않았습니다.

## 6. 4B(Qwen3-4B) 과정

### 이전 4B (yappang 데이터)
- 같은 채점기로 공식 111 추출 전체 일치 59.7, 시험 58 47.2, 추가 31 23.8, 시험 v7 34 25.0. 8B v5(97.0 / 91.7 / 90.5 / 81.2)보다 크게 낮았습니다.
- JSON 형식은 100% 지켰습니다.

### 새 4B (fixed-4 데이터, 11-09)
- 데이터: yappang 님과 합친 fixed-4. train 6,942줄 / val 314줄. 해시 일치, 평가 문장과 겹침 없음.
- 학습: RTX 4060 노트북, 3에폭 1,383스텝, 3시간 32분, 최종 val loss 0.0095.
- 평가 (`eval_q4b.py`, 234문항 세트):

| 세트 | JSON | 필드 정확도 | 완전 일치 |
|---|---|---|---|
| 공식 111 | 100% | 97.5% (목표 90) | 75.7% |
| haechan 123 (처음 보는 문장) | 100% | 93.4% | 54.5% |

공식 111을 8B와 같은 분류로 나누면:

| 구분 | 4B 새 모델 | 8B v5 | 이전 4B |
|---|---|---|---|
| 추출 | 91.0 (61/67) | 97.0 | 59.7 |
| 거절 | 35.7 (5/14) | 92.9 | - |
| 되묻기 | 60.0 (18/30) | 86.7 | - |

(분류별 합산은 평가 결과 파일의 정답과 출력을 직접 비교해 검증했습니다.)

- **좋아진 점:** 추출이 59.7에서 91.0으로 올랐고, 필드 정확도 97.5%로 목표 90%를 넘었습니다.
- **문제:** 20개 밖 개념 거절이 공식에서 0/8, 123건에서 0/10과 0/10입니다. 범위 밖 요청을 지표로 잘못 바꿀 위험이 있습니다. 지표 모호 되묻기도 2/9로 약합니다.
- 8B와의 차이에는 모델 크기와 데이터 차이가 섞여 있습니다. 같은 fixed-4로 8B를 돌려 보기 전에는 크기 효과만 따로 말할 수 없습니다.
- 학습은 yappang 인수인계본 `train_qlora.py`로 돌렸고, 저장소 최신본과 파일명 검사 한 줄만 다릅니다(학습 내용 영향 없음).

## 7. 배포(GGUF · Ollama) 문제 — 미해결

- v5 3에폭을 병합 → GGUF f16 → Q4_K_M → Ollama로 등록했습니다.
- Ollama에서 평가하면 추출 전체 일치가 **0%**였습니다(합친 HF 모델은 97.0).
- 확인한 것: 병합 모델은 정상, 프롬프트 템플릿은 원인이 아님. 의심 원인은 GGUF 변환, Q4_K_M 양자화, Ollama 0.40.14 실행기입니다.
- yappang 님은 Ollama 0.40.8로 같은 절차를 해서 정상 점수를 얻었습니다(Ollama·llama.cpp 버전 차이 의심).
- **발표·데모는 4060 노트북 Ollama 기준이라, 이 문제가 풀리기 전에는 최종 성능을 확정할 수 없습니다.**

## 8. 배운 점

1. 점수가 높아도 평가 문장을 반복해서 쓰면 낙관적입니다. 한 번도 보지 않은 문장 세트가 꼭 필요합니다.
2. 실패의 원인은 데이터가 아니라 학습 설정이었습니다. 정상 코드와 비교해서 찾았습니다.
3. 한 유형(거절)을 보강하면 다른 유형(추출)이 깎일 수 있습니다. v7이 그 예입니다.
4. 학습 손실은 학습 데이터에서의 값이라 성능 점수가 아닙니다. 모든 버전에서 손실은 계속 내려갔습니다.
