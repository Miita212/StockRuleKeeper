## 1. 가장 큰 위험: 서비스 성격이 출시 불가 항목에 걸릴 수 있음

서비스 오픈 정책의 **출시 불가 항목**에 아래가 있다.

| 출시 불가 항목 | 우리 서비스와의 관계 |
| --- | --- |
| 증권 등 금융 상품 서비스 | 증권사 연동이 없고 점검만 하므로 해당하지 않을 수 있음 |
| **투자 자문** (특정 종목 추천, 투자 전략 안내, 유료 투자 정보) | "내 원칙에 맞는 종목 목록"이 추천으로 읽힐 수 있음 |
| 투기성 콘텐츠 | 급등주, 떡상 같은 표현이 걸릴 수 있음 |

- 우리는 "추천이 아니라 내 원칙을 점검하는 서비스"다. 하지만 **문서에 판단 기준이 없어서** 해당 여부는 검수자가 정한다.
- 개발에 들어가기 전에 콘솔 채널톡이나 가이드라인(`/guidelines`)으로 **사전 문의**한다. 이 답이 없으면 만들고 나서 반려될 수 있다.
- 검수가 민감 주제는 최대 1주 걸린다. 11-10 제출 일정으로는 실제 출시가 불가능하다고 봐야 한다. 샌드박스 테스트까지만 현실적이다.

## 2. 앱 문구와 LLM 출력 문구

추천이나 전략 안내로 읽히는 표현을 피한다.

- 쓰지 않는 표현: "추천", "사세요", "유망", "수익 보장", "원금 보장", 목표주가, 매수·매도 시점
- 쓰는 표현: "내 원칙에 맞는지 점검", "충족/미충족", "기준값"
- **LLM의 `message` 문구도 같은 규칙을 따른다.** `off_topic` 안내문과 `unsupported_indicator` 안내문에서 "대신 ~로 원칙을 세워볼까요?"는 괜찮지만 종목을 직접 제시하면 안 된다.
- 판정서에 "투자 판단의 책임은 본인에게 있으며 매수·매도 권유가 아님"이라는 **고정 안내문**을 둔다. explain 의도의 `989번` 같은 질문("통과하면 사라는 뜻이야?")은 이 고정문으로 연결한다.
- 시뮬레이션 리포트는 과거 데이터에 대한 점검일 뿐 미래 수익을 말하지 않는다고 명시한다.

## 3. AI 관련 의무

- **생성형 AI 사전 고지와 결과물 라벨 표시가 필수**다. 입력 화면에 AI를 사용한다는 안내를 두고, AI가 만든 결과에는 AI 생성 표시를 단다.
- **AI 채팅·상담은 조건부 허용**이다.
  - 위험 키워드 필터가 있어야 한다. 우리의 `off_topic` 분류가 이 역할을 일부 하지만, 입력 단계의 키워드 차단도 따로 둔다.
  - **모델이나 프롬프트를 바꾸면 사전 검수를 다시 받는다.** 그래서 Day 7에 LLM·프롬프트를 동결하는 일정이 중요하고, 출시 뒤에는 파인튜닝 모델 교체도 검수 대상이다.
- 우리는 로컬 LLM(지표 변환)과 상용 LLM(리포트) 두 개를 쓴다. **검수 때 두 모델의 역할과 프롬프트를 모두 설명할 수 있어야 한다.**

## 4. 기술 제약

| 항목 | 내용 | 우리에게 미치는 영향 |
| --- | --- | --- |
| 개발 방식 | WebView(`@apps-in-toss/web-framework`, `npx ait init`) 또는 React Native | 현재 모바일 앱(390×844) UI를 WebView 웹앱으로 만드는 쪽이 가장 가깝다 |
| 렌더링 | 웹이면 **CSR/SSG만**, SSR 불가 | Next.js SSR 같은 방식은 쓰지 않는다 |
| 통신 | **HTTPS와 wss만** | 백엔드(FastAPI 게이트웨이)에 HTTPS가 필요하다 |
| 테마 | **라이트 모드** | 다크 모드 디자인은 필요 없다 |
| 내비게이션 | **앱인토스 내비게이션 바 필수** | 하단 바 5단은 별개로 두되 상단은 토스 바와 겹치지 않게 한다 |
| 로그인 | **토스 로그인만** | 자체 회원가입이 없으므로 원칙 저장은 토스 사용자 키 기준이다 |
| 금지 | `eval`, 외부 도메인 렌더링, iframe 중첩 | 외부 차트·뉴스 위젯을 iframe으로 붙이지 않는다 |
| 응답 | **반응 2초 이내** | 아래 5번 참고 |
| 설정 | `apps-in-toss.config.ts`의 `appName`은 콘솔 등록명과 일치 | 이름이 다르면 업로드가 실패한다 |

## 5. LLM과 맞부딪히는 부분 (해찬 담당)

1. **로컬 PC의 LLM을 그대로 서비스할 수 없다.**
   - 지금은 노트북 4060(8GB)에서 양자화 모델을 돌린다. 토스 앱의 WebView는 HTTPS 서버로만 호출할 수 있으므로 **외부에서 접근 가능한 서버(GPU 또는 CPU)** 가 있어야 한다.
   - 시연은 노트북 서버를 터널(HTTPS)로 노출하는 임시 방법이 가능하다. 단 상시 운영이 아니다.
2. **"반응 2초 이내"와 NFR-01(10초 내외)이 충돌한다.**
   - 2초 안에 화면이 반응하면 된다는 뜻이므로, 요청을 보낸 즉시 로딩 표시를 하고 결과는 비동기로 채운다.
   - 되묻기 선택지처럼 짧은 응답은 모델 크기를 줄이거나(예: 4B) 규칙 기반 빠른 경로를 두는 방법도 있다.
3. **상용 LLM의 API 키는 앱에 넣지 않는다.** 백엔드에만 두고 `.env`로 분리한다(팀 규칙에도 맞다). WebView 번들에 키가 들어가면 유출된다.
4. **위험 키워드 필터는 모델 앞단에 코드로 둔다.** 모델의 `off_topic` 판단에만 의존하지 않는다.

## 6. 데이터와 개인정보

- 사용자가 입력한 투자 원칙 문장은 개인의 투자 성향 정보일 수 있다. 저장 범위와 보관 기간, 로그에 원문을 남기는지 정해 둔다.
- 학습 데이터에 실제 사용자 입력을 쓰지 않는다. 지금 데이터(질문 리스트, 직접 쓴 문제)는 모두 우리가 만든 것이다.
- KIS와 OpenDART 응답을 그대로 재배포하는 것은 각 약관을 확인해야 한다. 앱에서 원본 데이터를 대량으로 보여 주지 않고 판정 결과 위주로 보여 준다.

## 7. 출시 절차

```
샌드박스 테스트 → 번들 업로드 → 토스앱 테스트 완료 → 출시 요청 → 검수
```

- 개인도 출시할 수 있다. 다만 결제, 광고, 토스 로그인 수익화는 **사업자 등록**이 필요하다.
- 민감 주제(투자)는 검수가 **최대 1주** 걸릴 수 있다.

## 8. 팀에서 정해야 할 것

1. 토스 인앱을 이번 과제 범위에 넣을지. 현재는 제외이고, 넣는다면 시연은 샌드박스 단계까지만 한다.
2. 포지셔닝 사전 문의를 누가, 언제 할지.
3. 앱 형태: 현재 모바일 앱(390×844) 설계를 WebView 웹앱으로 만들 것인지, React Native로 만들 것인지.
4. FR-02(가상 주식 앱)와 토스 인앱의 관계. 토스 안에서는 "증권 서비스처럼 보이는 가상 주식 앱"이 오히려 출시 불가 항목에 가까워질 수 있다.
5. 판정서 고정 안내문과 AI 사용 고지 문구의 위치.
